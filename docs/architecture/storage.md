# Storage, settings and backup

SQLite storage and its write lock, DB paths and migrations, the per-user settings registry, and backup/restore (desktop and Android SAF). Hard rules are summarized under **Invariants** in [CLAUDE.md](../../CLAUDE.md); this file holds how the subsystem works and why.

## Database

- **Storage** (`app/storage/database.py`): SQLite with automatic schema migration. Stores sessions (with `session_name`, `time_shamatha_90`, `score_metric_key`/`score_metric_name`/`avg_score` — the metric the session was scored on, #51 — and `score_targets` — the targets in force, in order, as JSON, #83 — columns), per-tick metrics timeseries (each tick with `score_key`/`score_value`/`score_target`, what it was scored on, #83; NULL in older rows), user profiles, per-user settings. CSV export support. `create_user` raises `UserExistsError` on duplicate name; `find_user_by_name` looks up by exact (case-sensitive) name. Per-user settings are a flat KV store (`set_user_setting`/`get_user_setting`, key = `user_{id}_{key}`); `set_user_json_setting`/`get_user_json_setting` wrap a value as JSON in one key (the pattern used by `saved_formulas`, and by per-graph series / active-formula lists). The connection is accessed through a single self-healing `_conn` **property** (backing `_conn_obj`) so no read/write path can deref a `None` connection: if the conn was closed while the app is still running it reopens the DB file (lock-guarded reconnect); once `mark_shutting_down()` is set it returns a **null connection** (`_NULL_CONN`) that swallows writes and returns no rows, so late access from any path (reads, writes, the daemon tick thread) is a **benign no-op** — never a crash, never a reopen that resurrects a closed process or clobbers a freshly-restored DB. `on_stop` and `_do_restore_and_restart` both `mark_shutting_down()` before `close()`; `on_pause` also skips the settings flush while `_restoring`. So editing settings never silently vanishes, teardown never crashes, and a restore is never clobbered. `delete_user` **purges** the user's sessions, metrics, and `user_{id}_*` settings in order (FKs are declared but not enforced — no `PRAGMA foreign_keys`/cascade — so an explicit ordered delete is required; uses GLOB not LIKE so the literal `_` in the key prefix isn't a wildcard). Without it, deleting a profile orphaned its sessions (which then surfaced in the All-Users view), metrics, and settings rows forever. The confirm (`SettingsScreen._confirm_user_delete`) therefore states the profile's session count and that they are deleted with it — it used to say only "All their settings will be lost."
- Database opens with `check_same_thread=False` so the daemon tick thread can write metric batches — and that shared connection is why **every runtime write goes through `DatabaseManager._write()`**: one transaction at a time under `_write_lock` (RLock), commit on success, rollback on error. Without it the UI thread's commit could end the tick thread's `save_metrics_batch` transaction mid-batch, raise "cannot commit - no transaction is active" into a UI callback, or drop a batch. The null connection has a no-op `rollback`. `tests/test_database_write_lock.py` covers blocking, a two-thread race with exact row counts, and rollback.
- Android DB path always uses `app_storage_path()` (not `/sdcard`) for stable path across launches. Old DB auto-migrated on first run. `KIVY_KEYBOARD_MODE=systemanddock` + `softinput_mode=below_target` set for Android TextInput stability.
- Desktop DB path resolves to platform user-data folder: Linux `${XDG_DATA_HOME:-~/.local/share}/EEGMeditation/`, Windows `%APPDATA%\EEGMeditation\`, macOS `~/Library/Application Support/EEGMeditation/`. One-time migration copies any pre-existing DB from next-to-binary or project root; the old file is left in place for manual rollback.
- DB migrations (Android `/sdcard → app_storage_path` and desktop legacy → user-folder) surface failures via `crash_handler.queue_pre_app_error(label, detail)`, replayed by `EEGMeditationApp.on_start()` through `report_soft_error`. **Project policy:** never `except (PermissionError, OSError): pass` — surface a diagnostic instead.

## Per-user settings

- **Per-user settings registry** (`app/settings/registry.py`): the ~20 scalar per-user settings (threshold, audio metric/index, feedback+reward source/path, alert toggles, timer enable/minutes/sound, line width, rotation, graph zoom, marker hotkey, stats mode, device mock, **theme**) are declared once as `Setting(key, default, parse, serialize, get, set)` descriptors, built in `_build_settings_store()` (in `build()`, after the screens exist and BEFORE any user load, so each default is snapshotted from the app's constructed initial state). `SettingsStore.load(uid)` applies each setting as its parsed stored value **or its default when absent/invalid** — it ALWAYS applies a value, so a fresh/partial user can never inherit the previously-active user's in-memory value (the leak class). `save(uid)` serializes all in **one transaction** (`DatabaseManager.set_user_settings`, one `executemany` + commit, not one commit per key); `persist(uid, key)` writes one key immediately (change-callback path), suppressed while loading. `_persist_user_setting(key)` (key only — the store reads the live value) catches `sqlite3.Error` → soft error; **continuous inputs** (the threshold slider, the timer-sound text field) go through `_persist_user_setting_later(key)`, a per-key Kivy `Clock` trigger restarted on every change (`_PERSIST_SETTLE_S` = 0.5 s), so a drag or typed path is one write, not one fsync per step/keystroke on the UI thread. `timer_sound`'s getter reads its widget (like `timer_enabled`/`timer_minutes`). `_load_user_settings`/`_save_user_settings`/`_persist_user_setting` are thin calls into the store; the rich **aggregates** (custom formulas, saved programs/formulas, active program, per-graph series) keep their existing dedicated handling (they already reset correctly). **Theme is per-user** (its descriptor, `get=C.theme_name`/`set=C.set_theme`); the global `theme` key (`theme_seed(db)`, never written since) is only the default for a profile with no theme of its own, so existing users keep their theme and unset users default to it; `build()` builds the UI in `startup_theme(db)` — the startup profile's theme, else that seed — so the profile load applies the theme already showing (a no-op); the text size starts the same way (`startup_text_size`). Both are `startup_value(db, setting)`: the startup profile's value read as `SettingsStore.load` reads it (`stored_value`: the stored value if present and valid, else the default). The theme setting (`theme_setting(seed)`) rejects an unknown stored name, so it loads the seed — `set_theme` ignores an unknown name, which kept the previous profile's palette. Codecs: `BOOL/INT/FLOAT/STR` (parse, serialize) pairs. Replaces the ~100 hand-written save/load/default sites that each behaved on their own logic (and each leaked on absent-key). Storage is unchanged (existing `app_settings` KV via `get/set_user_setting`) — normalizing that table is a deliberate deferred follow-up.
- Settings (and the session-end card's unsaved notes) saved in `on_pause()` (Android) and `on_stop()` (desktop) via `_flush_on_leave` so they persist when OS kills backgrounded app. `on_pause()` always returns `True` — per Kivy docs, returning `False` stops the app rather than "refusing to pause" (counter-intuitive but documented).

## Backup and restore

- **DB backup/restore** (`app/storage/backup.py`): `online_backup_to_tempfile` (SQLite online `Connection.backup()` into an internal temp file), `make_backup` (temp + `copy_file_atomic`, desktop), `validate_backup` (checks for required tables), `restore_backup` (validates, `copy_file_atomic`, then removes the replaced DB's `-wal`/`-shm` so SQLite can't replay them onto the restored file). **Every app file copy goes through `app/storage/fileops.copy_file_atomic(src, dst)`** — bytes only, into a temp file beside `dst`, fsync, `os.replace` (so `dst` is untouched or complete) — never `shutil.copy2`: in Android app storage copying the SELinux label raises EACCES, which the phone's Python 3.11 `shutil` doesn't ignore (3.12 does), *after* the data is written, so Restore replaced the DB and then reported `restore_failed` and skipped the relaunch (#63). The same EACCES is the harmless Kivy `Error when copying logo directory` on the first launch after an install. `discard_file(path)` is the shared remove-and-log for temp/leftover files. Android backup/restore go through the Storage Access Framework (`app/storage/android_saf.py`) since scoped storage blocks direct `/sdcard` access. Used by Settings → Data Backup section.
- Backup/Restore lives in `app/storage/backup.py`. Backup uses SQLite's online `Connection.backup()` API (transaction-safe). **`online_backup_to_tempfile(db)` writes the online backup to a temp `.db` beside the live DB (internal storage) and returns its path; callers byte-copy or stream it out, then delete it** — SQLite returns `SQLITE_CANTOPEN` ("unable to open database file") if asked to open/lock a DB directly on Android FUSE storage (`/sdcard`) or a `content://` URI, so the destination is never opened by SQLite. `make_backup(db, path)` wraps it + `copy_file_atomic` (desktop / real filesystem paths). **Android uses the Storage Access Framework** (`app/storage/android_saf.py`), not a hardcoded path — scoped storage (targetSdk 30+) forbids direct `/sdcard` writes regardless of `WRITE_EXTERNAL_STORAGE`/`MANAGE_EXTERNAL_STORAGE` (the latter doesn't even exist on API 29). Backup: `_run_backup_saf` → SAF `ACTION_CREATE_DOCUMENT` save dialog (user picks location) → `online_backup_to_tempfile` → `android_saf.write_file_to_uri` streams the temp through the returned `content://` URI via `ContentResolver.openOutputStream`. Restore: `_run_restore_saf` → SAF `ACTION_OPEN_DOCUMENT` → `android_saf.read_uri_to_file` streams the picked file to an internal temp `_restore_candidate.db` (`FileUtils.copy`, API 29+) → normal validate + restore; `_confirm_restore(path, discard_after=True)` deletes that temp on every exit (invalid file, Cancel, after the restore), a failed read deletes the partial one, and a desktop user's own picked file is never deleted. No storage permission, survives uninstall, works API 29→34+. `android_saf` routes results via a request-code registry bound once to `android.activity.on_activity_result`; all pyjnius imports are function-local so it imports cleanly off-Android. Desktop backup/restore worker catches `(OSError, sqlite3.Error)`; the SAF worker catches broadly (pyjnius boundary) and `report_soft_error`s. Restore **refuses to run while a session is active** — running, paused, OR still in the BT-connect wait (`_session_pipeline_live()`: state RUNNING/PAUSED, `_waiting_for_bt`, or a live tick thread; the same window `_on_user_delete` discards on active-profile delete). Checked at `_on_restore_pressed` and again in `_do_restore_and_restart` (the DB shutdown would silently drop the session); a close or copy failure there surfaces `report_soft_error` and calls `DatabaseManager.reopen()` (clears the shutting-down latch and reconnects the **same** object — the settings store and every other holder keep a live reference; swapping in a new manager left them on the null connection, so every later settings write was silently dropped). `make_backup` refuses a target that resolves to the live DB (the desktop save picker opens in the DB folder; `os.replace` would leave the open connection writing to the swapped-out file). validates the file (must contain `users` and `sessions` tables), `mark_shutting_down()`s + closes the live DB, copies over `APP.DB_PATH`, then force-restarts via the "Please relaunch" popup (`_show_relaunch_popup`, re-shown from `on_resume` if Android resumes the process instead of killing it) → `App.stop()` (in-memory caches reference the old DB, simpler to restart). A `backup()` on the shut-down DB raises `sqlite3.OperationalError` (a silent no-op would write an EMPTY backup the user later restores). Desktop uses Kivy `FileChooserListView` save/open popups. **Mid-session backup freshness (issue #30):** `_on_backup_pressed` calls `_save_user_settings()` (main thread) before dispatching to the SAF/desktop worker, so a backup taken mid-session isn't a stale pause/stop snapshot; additionally every scalar per-user setting persists on change via the settings registry (see Per-user settings above), so they also survive an Android force-kill. `_save_user_settings` catches `sqlite3.Error` and reports a soft error (it runs from UI callbacks — backup, pause, profile switch — so an escaping error would open the fatal dialog; a failed flush no longer aborts the backup). It **never touches `_timer_state`**: a running session — especially a program, which force-enables the timer and seeds its countdown from the program total — OWNS it, and re-applying the Settings timer widgets on a pause/backup flush silently killed or shifted auto-stop. Session start re-applies enabled/duration, and `_on_timer_sound_change` keeps the gong path current, so nothing needs an idle sync. Both backup workers checkpoint a running session first (`_checkpoint_session`, see Persistence in [session.md](session.md)), so a mid-session backup holds it as of the backup. The restore confirm (`_confirm_action`) states it replaces the **entire DB** — with the profile and session counts from `get_record_counts()` — and both backup paths end in `_report_backup_saved(location)`: a **Backup saved** `_info_popup` carrying `_BACKUP_SOUND_NOTE` ("custom sound files are not included"; the SAF path omits the content:// URI), a short status line, and a log line — the old status-line-only confirmation was a small muted label at the bottom of a collapsed section and went unseen on-device. The suggested file name is `backup.backup_filename(user_name, now)` → `eeg_backup_<profile>_<YYYY-MM-DD_HH-MM>.db` (profile first, so the narrow SAF name field still shows it; path separators, whitespace and FAT-illegal characters become `_`; no usable name → just the time). Missing custom sound files are reported by **one** `_warn_missing_sound_files(feedback_sources, timer_path)` report at session start and from both Test buttons (two separate `report_soft_error` calls raced: the second was dropped while the first dialog was pending); the Test buttons pass `force=True` — user-initiated, like Copy Diagnostics — so the shared label's 60 s cooldown after a session-start report can't hide the file the user just tested, so `play_timer_sound`'s fallback to the default gong is never silent.

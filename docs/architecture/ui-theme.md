# UI foundation: theme, widgets, modals

Navigation, the theme system and runtime theme switching by colour role, shared widgets, and the one modal style. Hard rules are summarized under **Invariants** in [CLAUDE.md](../../CLAUDE.md); this file holds how the subsystem works and why.

## Navigation and theme

**Navigation:** 3-tab bottom bar (Session / History / Settings) via `BottomNav` in `theme.py`. First-run wizard shown when no users exist.

- **Theme system** (`theme.py`): Centralized `C` color accessor (4 palettes: Dark Blue, Dark Green, Light Cream, Light Green), `F` font sizes, `S` spacing. `format_duration(seconds)` — smart time display (seconds if <1m, minutes if <1h, hours otherwise). `make_scroll_popup(title, rows, footer=None, *, est_rows=None, ...)` — the shared builder for every list-style select dialog (series picker, saved-formula chooser, program picker, duration picker): the `rows` scroll inside a `ScrollView` with the `footer` pinned below, sized to content but capped at 85% of the window so long lists scroll instead of overflowing. `est_rows` overrides the height estimate when a row is itself a multi-row grid. `make_message_popup(title, message, buttons, *, auto_dismiss=True)` is the one message modal (its text is always `C.TEXT`; a success/failure tone belongs to the title and the button) built on it (see `_confirm_action` below); both are `ThemedPopup`s (see **One modal style**). Custom widgets: `StyledButton` (rounded, press feedback, MDI icons, outline mode; `vertical=True` for 2-row icon-top/text-bottom layout), `Card`, `Divider`, `ThemedAccordion`, `PresetRow`, `RevealBox`, `BottomNav`. A theme switch repaints everything live, by colour role (see **Theme colours** below). `StyledButton` resolves its text/icon colour by **role** (re-applied on bg/theme change, never a frozen snapshot): no `text_color` (or `text_color = None`, which returns to it) → **AUTO** = `readable_fg(bg_color)` picks the light or dark glyph with the higher WCAG contrast against *that button's* background (fixes both light-icon-on-light-accent and dark-icon-on-saturated-fill — the better of the two glyphs, ≥4.4 CR on most fills; the palette's mid-tone fills cap it at ~3.9:1 (Light Cream `PRIMARY`, Dark Green `PRIMARY_DIM`). A **selected** state is an accent fill with AUTO (`text_color=None`): `C.TEXT` on a bright fill was 1.5–2:1 in the dark themes); a palette `text_color` (`C.X`) follows the theme through `ThemedMixin`; any other colour is fixed. **Disabled** dims both label and icon to 60% of `readable_fg(bg)` (a dimmed auto-contrast grey, ~4:1, theme-independent — the theme's light `C.TEXT_MUTED` washed out on light cards); the dimmed colour is written to the labels' **`disabled_color`** as well as `color`, because Kivy's `Label` style draws `disabled_color` (default white@.3 → invisible on light cards) whenever the widget is disabled — setting only `color` left the disabled action-bar glyphs blank on light themes. **pressed** darkens the background (glyph colour unchanged) **and** raises an edge-visible press ring (issue #33): `on_state` snaps `_ring_alpha` to `_RING_MAX` on `down` and `Animation`-fades it to 0 over `_RING_FADE` on release, so the cue survives the fingertip and lingers on release (the old darken-only cue was invisible under a finger on mobile). The ring is a `Line` drawn in `_redraw` at `_ring_rgb()` = `C.TEXT` — contrast derives from the **surrounding surface** (light on dark themes, dark on light), NOT the button fill, same rule as the graph expand glyph; `readable_fg(fill)` would give a dark ring on a bright accent button that then vanishes on a dark theme. `flash_confirm(text="Saved", icon=None, confirm_color=None, duration=1.1)` is the action-confirmation cue (issue #33 E): it morphs the label (and optionally the icon / fill) to a success state, then `Clock`-reverts to the **true** original (reentrancy-safe — a repeat tap restarts the timer without capturing the intermediate state). Main-thread only. Wired into the program **Save** success path via `SettingsScreen.confirm_program_saved()` → `AppManager._save_program` (text-only button ⇒ `confirm_color=C.SHAMATHA` green pop, since an MDI check glyph would be tofu in the label's Roboto font). The class-level `text_color` default was a frozen import-time ~white that rendered icons invisible on light themes (disabled buttons hit ~1.25 CR); theme switching is a pure live-refresh (no screen rebuild), so colours must carry their role. **`RevealBox(content_height)`** is the sanctioned touch-safe way to conditionally show a row: `set_content(*widgets)` once, then `reveal(bool)` — it **detaches** the children when hidden (empty box at height 0) rather than collapsing them in place. Never hide interactive content with `height=0`/`opacity=0`/`disabled=True`: Kivy's `Widget.on_touch_down` does `if self.disabled and self.collide_point(...): return True`, so a hidden-but-attached disabled widget *consumes* taps on whatever it overlaps (a known Kivy bug, unfixed in 2.3.x; `on_touch_up`/`on_touch_move` ignore-without-consuming). `tests/test_touch_regression.py` enforces this: it mounts screens in a real window and flags both actual dead zones and the collapse-in-place anti-pattern (a disabled, collapsed container still holding interactive children).
- **Theme colours** follow a runtime switch by role, not by snapshot (#38). `C` is a `_ColorAccessor`; every colour read from it (`C.BG_CARD`) is a `ThemeColor`, a tuple that also carries its `role`; `list()` or a slice of it is a plain, fixed colour. A widget colour property given one records the role and is re-applied from the new palette on every `C.set_theme(name)` (applying the theme already active is a no-op — every profile activation applies its stored theme); any other value stays fixed, and assigning a literal later drops the role. Roles are recorded by `ThemedMixin.__setattr__` (`color`, `disabled_color`, `bg_color`, `bg_pressed`, `text_color`, `background_color`, `foreground_color`, `cursor_color`, `hint_text_color`, `selection_color`, `title_color`, `separator_color`, `overlay_color`), mixed into `ThemedLabel`, `ThemedTextInput`/`CenteredTextInput`, `StyledButton`, `Card`, `Divider` and `ThemedPopup` (`SectionLabel`/`IconLabel` are `ThemedLabel`s). A role resolves in the current palette at assignment, so a `C.X` stored before a switch (e.g. `PresetRow`'s selected colour) still paints the new one. Every Label and TextInput in `app/ui` is the themed one: `tests/test_theme_switch.py` fails on an import from `kivy.uix.label`/`kivy.uix.textinput` outside `theme.py`. Before this, only what registered a listener and re-read every colour it owned repainted — a stats `Card` kept its light background while its labels turned light (white on white), and the session detail, the Settings sections and the summary card kept the old palette until a restart. Canvas: `ThemedColor(C.X, alpha=None)` is a `Color` instruction that re-reads its role on a switch, and `fill_background(widget, C.X)` is the one background fill for screens and overlays. Widgets that rebuild their canvas from the palette on redraw (`ScrollableGraphWidget`, the History calendar and 14-day bars, `StyledButton`'s disabled/outline fill and press ring, `BandTotalsView`, the duration picker) register that redraw with `C.add_listener` (once however often registered); listeners run after the roles are re-applied, a bound method is held weakly and its entry drops itself when the widget dies (they used to keep every button ever built alive), and a failing listener or widget repaint is logged without stopping the switch. To save and restore a themed colour use `widget.assigned_color(prop)` — a `list()` copy freezes it (`flash_confirm` restores its fill this way). Code that keeps colours and unpacks them into canvas `Color`s draws `C.resolve(color)`: a palette colour in the current palette, anything else as it is — module-level series dicts like `live_session.METRICS_COLORS` are read once at import, and `ScrollableGraphWidget.series_color` resolves them, so a line and its legend swatch agree. The Settings → Theme highlight is a listener, so it also follows a theme applied by a profile switch. `build()` used to build the UI in the global `theme` key's palette, which nothing writes since the theme became per-user, so a profile on another theme was switched at every launch — before the role mechanism that left the stats card, the Raw EEG toggle and more in the build palette at every start; it now builds in `startup_theme(db)` (see the settings registry in [storage.md](storage.md)). Measured 2026-10-02 on desktop: a switch with History (300 rows), Live, Settings and the session detail built takes ~180 ms (was ~120 ms when far less repainted); on a themed widget the `__setattr__` hook adds ~0.16 µs to a non-colour attribute set and ~0.3–0.5 µs to a colour set, and a 300-row History build was unchanged within noise. `tests/test_theme_switch.py` builds each screen in one palette, switches, and checks every widget colour property and canvas `Color` for a colour from the old palette — after the switch and after each state reachable later (every Settings section opened, the summary card, select mode, both History views, every session-detail tab).

- **Text size** (`F`, #76) follows a runtime change the way colours follow a theme switch. Every font size comes from `F`: the roles (`F.BODY`, `F.SMALL`, …) and `F.px(n)` for a size off them (a graph's canvas labels through `_make_text_texture(size=…)`, Kivy's own defaults: `ThemedLabel` and `ThemedTextInput` default to `F.px(15)`, Kivy's 15 sp). Each is a `FontSize`, a float that also carries its `base`, its size at the normal text size, and its `cap`; arithmetic on it is a plain, fixed size. `ThemedMixin.__setattr__` records a `font_size` or `title_size` given one in `F._sized` (widget → {property: (base, cap)}) and stores the plain size: Kivy's numeric properties reject a float subclass, so a `FontSize` given to a widget that isn't themed raises at once (`ThemedButton` is Kivy's `Button` themed, for the profile screen's buttons). Any other value drops the record and stays fixed — `F.glyph(n)` is an icon in fixed chrome (the bottom nav's 46 dp bar). A size read before a change (a `LegendBar`'s stored `F.TINY`) still resolves at the size in use. `F.set_scale(scale)` (a no-op for the size in use, which a profile load applies at startup) re-sets the roles, re-applies every recorded size, then calls the listeners registered with `F.add_listener` (`_Listeners`, the same registry `C.add_listener` uses: once per callback, a bound method held weakly, a failure logged without stopping the change). The listeners are what was sized from text when drawn: the graphs redraw (their labels and the margins those take), the band table re-renders, History's charts redraw, the saved card re-lays its notes field, the Session screen's status line re-fits, the Settings picker selects the size in use. A `StyledButton`'s text and icon labels are plain Kivy labels that follow its `font_size` and `bold`. `text_size` is a per-profile registry setting whose getter and setter are `F.SCALE` and `F.set_scale`, so the picker and a profile switch both apply it at once (the sizes on offer are `TEXT_SIZES`, 100 / 125 / 150 %); `build()` still builds at `startup_text_size(db)`, the startup profile's size, so loading that profile changes nothing it just laid out. `tests/test_text_size.py` fails on a size given directly (`font_size=dp(…)`, `sp(…)`, Kivy's string units), which would ignore the setting. The app doesn't follow Android's system font size: every size is `dp`.
- **Boxes that hold text follow it; text in a box that can't stops growing.** At 150 % a fixed box cuts text off or wraps it, so:
  - a multi-line label takes its text's height (`fit_height_to_text(label)`; the same test fails on a multi-line `ThemedLabel` with a fixed height), and a row of a wrapping label beside fixed-height controls is as tall as the label, at least its old height, with the controls centred (`fit_row_to_text(row, label, min_height)`: Settings' checkbox rows, Marker Hotkey, History's list heading);
  - a box sized for its text takes `F.box(n)` (a plain `dp(n) * F.SCALE`, up to a cap when its text is capped) and re-reads it in an `F.add_listener` (the band table's rows and columns, the 14-day chart's margins and label boxes, the saved card's notes field, the Session screen's status line); a box whose text changes as well sizes itself to it (the timer length beside Start, `_fit_width`: as wide as its capped text, "105m", at least 20 dp);
  - a `StyledButton` fits its sides to its text (`_fit_padding`): `S.BTN_PAD` (12 dp) when its text (or icon) fits on one line, narrower down to `S.BTN_PAD_NARROW` (2 dp) when the button is too narrow for it, leaving 2 dp spare, measured (`text_width`, also the saved card title's cut) once per text, icon, size and weight; `set_icon` swaps the glyph before `icon` changes, so the sides fit the glyph shown. A fixed 12 dp left a 40 dp button 16 dp (History's Cal / 14d, the duration presets and a segment's End cue / Feedback wrapped, an icon-only `FoldChevron` cropped its glyph); a text measured with nothing spare wrapped on the phone, whose whole pixels round differently. `padding=` fixes the sides instead;
  - where the box can't grow with its text (a fixed strip of columns, a status line), the text is `F.capped(size)`: it follows the text size up to `F.CAPPED_MAX` (120 %), or a cap of its own. The Session screen's status line, its timer length (the bottom bar's width is fixed: grown to 150 %, "105m" squeezed Start onto two lines on the phone), its stat strip's titles (110 %, "Distraction" in a fifth of a 360 dp phone) and LIVE toggle, and a program's segment row and its header, are capped; everything else grows to 150 %. A cap is added only where a test fails without it.

  `test_no_text_outgrows_a_box_at_the_largest_size_that_it_fits_at_normal` builds the main screens (the Session screen, with no timer and a 105 min one, and its saved card; History in both views, with a day picked; every Settings section and a program's segments; the session detail; Profiles; the first-run wizard's two steps, since picking an existing profile there applies its size before step 2; the bottom nav) at both sizes in a 360 dp frame and fails on any text that fits its box at the normal size and not at the largest. It measures the text, not the label's texture, which is exactly the box when the text area is pinned to it (and cut). A centred line has room above and below its letters, so a box up to 0.3 em shorter only trims that; a pinned label must also fit 1 dp narrower, since a text with nothing spare wraps at another density. A text field must hold its text or hint (wrapped when multi-line, from the top down, so no room is allowed). A label also mustn't reach past its parent (a chart's axis label). `test_the_largest_size_also_fits_at_a_phones_pixel_density` runs that, the narrow-button test and `test_the_timer_pill_holds_every_timer_on_one_line` (every length from 1 to 120 min, no timer and a program's P, at both sizes) again in a process at 2.75 px per dp, the test phone's: Cal, the 14-day chart's "100" and the stat titles fit at 1 px per dp and wrapped on the phone. `test_a_screen_switched_to_a_size_is_laid_out_as_one_built_at_it` builds each screen at the normal size, switches to the largest, and compares every widget's text, font and size with the same screen built at the largest — switched before a state is reached (a Settings section opened while its content was detached) and while it is shown.

## Widgets

- **Icons** (`app/assets/fonts/materialdesignicons-webfont.ttf`): Material Design Icons font, registered as `'Icons'`. `ICONS_AVAILABLE` flag for graceful fallback if font missing.
- **App icons** (`app/assets/icons/`): Generated EEG brainwave icon (512/192/128/48 PNG + ICO + ICNS), presplash for Android.
- **Shared widgets** (`widgets/`): `UserPickerForm` (used by wizard step 1, first-run popup, and Settings → User Profile) — existing-profiles list + name input + duplicate-name "Use existing 'X'" / "Change name" inline UI. `LoadingOverlay` (`widgets/loading_overlay.py`) — app-global modal spinner (status + animated dots on the theme's `ModalPanel` over a dim) mounted by wrapping the app root in a `FloatLayout`; shown via `EEGMeditationApp.show_loading(text, delay=0.0)`/`hide_loading()`; with a `delay` it takes taps at once and paints only once the delay has passed, so a job that ends sooner never flashes it. Because it animates via `Clock`, the caller must move the long work off the main thread or the overlay can't paint.
- All legends use one wrapping `LegendBar` (`app/ui/widgets/legend.py`, a `StackLayout` flow): `set_items([(text, rgba)])` flows colored labels and wraps to extra rows (each label sized to its text), so many series (6 metrics + 3 custom formulas) stay readable instead of overlapping in a single-row `BoxLayout`. Used by the live metrics/band legends, the diary legend, and the fullscreen legend.
- `_AccordionSection` (`app/ui/theme.py`) binds `_content.minimum_height` to `_update_height` so its inner `_scroll.height` tracks growth from grandchildren added after the section was opened — without it, lists populated post-open (e.g. `populate_bt_devices` after the user expanded Device) get clipped to the original empty-content height.
- `theme.CenteredTextInput` — `TextInput` subclass; `halign="center"` (native Kivy 2.3) + padding-based vertical centering (`_recenter` adjusts `padding[1]`/`padding[3]` to `(height - line_height) / 2` on each resize, since Kivy has no `valign`). All single-line inputs use it; the two multiline fields (diary notes, live-session quick notes) keep plain `TextInput`.

## Modals

- **One modal style, in the active theme.** Every popup is a `ThemedPopup` (a `Popup` subclass, so `isinstance(w, Popup)` checks hold): Kivy's always-dark 9-patch chrome is turned off (`background=""`, transparent `background_color`) and `paint_panel` draws the window behind Popup's kv frame — the screen colour `C.BG`, rounded, with a `C.BORDER` edge — over a `C.BG_OVERLAY` dim, with a bold centred `C.TEXT` title (`F.H3`) and a thin `C.BORDER` separator; body text is `C.TEXT` and rows/cards keep their `BG_CARD`, so a modal reads like a small screen. The in-screen modal cards — the session-end card, the connection overlay and the `LoadingOverlay` — are a `ModalPanel` (the same `paint_panel`, title and separator) on a `ModalScrim`: the `C.BG_OVERLAY` dim, which like a popup's overlay keeps taps from reaching the screen behind (a tap on the dim area under the end card or the connection card used to press Start/Stop/Mark). The end card is as tall as its content when that fits and otherwise the space there is, scrolling the rest (centred, a taller card pushed OK off screen; the end card itself, 260 dp with its margin in two columns, fits the ~314 dp a 360 dp landscape phone has above the bottom nav — `test_the_session_end_card_fits_a_landscape_phone_above_the_bottom_bar`); the connection card attaches Retry only on failure (a hidden one left a blank slot). A toast is `C.TEXT` on `paint_panel`. The diagnostic dialog (`CrashDialog`) is built from the themed widgets, and from stock Kivy ones (`_plain_makers`, the one `# plain-ok:` exception to the popup-import guardrail) if building the themed one raises — the crash may be in the theme layer — resetting `in_dialog` if both fail so later reports aren't dropped as re-entrant. Every Cancel/Close is `cancel_button()` (`C.TEXT_SECONDARY` on `C.BG_CARD`; there were five styles, two of them 2.5–2.9:1). A `ThemedPopup` with `size_hint=(w, None)` and no `height` is as tall as its content, capped at 85% of the window like `make_scroll_popup` (fixed `size_hint` heights left half-empty panels); list pickers go through `make_scroll_popup`, messages through `make_message_popup`. `ThemedTextInput` defaults to the theme's input colours, and `ThemedFileChooser` draws its entries and column headers in the theme's text colours (Kivy's are white) and tints a selected entry from `C.PRIMARY` (Kivy's fixed grey made it dark on dark in the light themes). The old always-dark chrome forced a light `POPUP_TEXT` constant, and a themed `C.TEXT` label inside a popup (the first-run welcome, "No saved programs") came out dark on dark in the light themes. `tests/test_modal_style.py` opens each kind of modal in all four themes and checks every visible label against the surface it is drawn on (its button, card, input or the panel) for 3:1, checks each is drawn with `paint_panel`, and fails on an import from `kivy.uix.popup`/`kivy.uix.filechooser` anywhere in `app/` outside `theme.py`.
- `theme.make_message_popup` — the one message modal, used by `_confirm_action(title, message, ok_text, on_ok, ok_color)` (program save-overwrite / delete / load, and Restore), `_info_popup`, the profile- and session-delete confirms and the diary export result, built on `make_scroll_popup`: the message `Label` is measured wrapped (`text_size` + `texture_update`) so the popup sizes to it, capped at 85% of the window, scrolling beyond — a label with `text_size` bound to a fixed-height popup made Kivy silently drop the lines that didn't fit (at 732×360 the restore warning lost half its words, including "This cannot be undone"). Body text is `C.TEXT` on the modal panel (see **One modal style**). Save upserts by name so re-saving an already-loaded program overwrites it; load reflects the name back so the next save goes to the same record.

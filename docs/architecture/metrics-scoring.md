# Metrics and scoring

The metrics engine, custom formulas, and how a session is scored: the scored metric (#51) and the threshold in force (#83). Hard rules are summarized under **Invariants** in [CLAUDE.md](../../CLAUDE.md); this file holds how the subsystem works and why.

## Metrics engine

- Update loop runs at 2Hz (`AppConfig.UPDATE_FREQUENCY = 0.5s`); a graph holds up to `APP.GRAPH_POINTS_MAX` = 21600 points (3 h).
- Band powers are sqrt-normalized to relative units before metric formulas.
- **Metrics pipeline** (`app/metrics/engine.py`): Consumes raw band powers, computes meditation score, shamatha score, distraction, sinking, subtle distraction. **Distraction & sinking are ported from the original Vernihor app** (`reference_distraction`/`reference_sinking`), not sigmoids: both are gated to 0 by alpha dominance and modulated by `(140 − S')` where `S'` is shamatha *before* the final −20 offset and clamp (exposed via `MetricsEngine.last_s_prime`); distraction is the raw `100·(β1+β2)/α1` ratio, sinking is `(45 − a2p)/0.26` then gamma-damped. Their gates use `sqrt_pct_8band` — `round(sqrt(raw/P8)·100)`, an 8-band sqrt-relative percent (0–100), distinct from the 6-band `compute_sqrt_relative_bands` the shamatha formula uses. Subtle distraction still uses sigmoid normalization of short-window variance. Each saved session is stamped with `MetricsEngine.ENGINE_VERSION` (`sessions.engine_version`, "2" = ported formulas; "" = pre-versioning sigmoid era) so stored values stay attributable — the diary reads stored distraction/sinking, it does not recompute them, so old sessions render unchanged. Uses rolling buffers from `app/eeg/buffer.py`. Power-line noise detection in `app/metrics/noise_detector.py`.
- **Custom formula engine** (`app/metrics/custom_formula.py`): AST-parsed user-defined expressions with whitelisted functions and `avg(expr, N)` windowed averages.

## Custom formulas

- Three custom-formula evaluators are keyed by `FORMULA_KEYS = ("custom_formula", "custom_formula_2", "custom_formula_3")` in `app_manager.py`. `_formula_for_key(key)` maps a series key to its `CustomFormulaEvaluator`; `_formula_slots[i]` holds the evaluators; `_formula_names[i]` holds the display names (default `"Custom 1/2/3"`). Slot names are pushed to the graph via `graph.set_series_name(key, name)`. Active names + expressions persist as `active_formulas` (JSON list of `{name, formula}`, per-user); the audio-driving slot index persists as `audio_formula_index` (flat KV string, per-user). At load time `_read_active_formulas_with_migration` seeds slot 1 from the legacy `custom_formula` scalar if no JSON exists yet. The audio binding: when "Custom Formula" is selected as the audio metric, `_audio_metric_key = FORMULA_KEYS[_audio_formula_index]`; if that slot's evaluator is invalid (empty or parse error), the noise-volume step falls through to shamatha. `_audio_drive_key()` resolves the live drive key: the program's transient `_program_audio_key` while a program runs, else the user's baseline; it falls back to `shamatha_score` for an invalid formula slot **or** a `PROGRAM_FORMULA_KEYS` value outside a program (those are absent from `metrics` → would read 0 → constant max noise). `_baseline_audio_metric(key)` keeps program slots out of the persisted/baseline `audio_metric` (sanitized on both save and load — load also heals a previously leaked value). The on-graph series picker shows a **Choose…** button next to each custom-formula row on the *live metrics* graph; pressing it opens a library popup (`_open_saved_formula_chooser(slot_idx, toggle_btn)`), and choosing an entry calls `_assign_saved_to_slot(slot_idx, entry)`, which updates the evaluator, the graph name and visibility (`_on_formula_slot_change`, persisted) and the settings UI in one step. All three formula series share one Y-axis (scale 200, reference at 100).
- Active custom formulas are recorded at save time so the diary can replay them: every checkpoint (`_checkpoint_session`: the 60 s flush, leaving the app, a backup, the final save) passes `custom_formulas=self._session_custom_formulas_json()` — a JSON string of the valid slots (`name`, `formula`, `visible`, `drove_audio`). `save_session(..., custom_formulas: str = "")` stores the **already-serialized string** (the contract; callers `json.dumps` at the site). It's built from `self._formula_slots[i].formula` + `graph.is_visible(FORMULA_KEYS[i])` (a pure dict read, tick-thread-safe). On diary load the diary recomputes from these defs (see [session-detail.md](session-detail.md)) rather than trusting the stored custom_formula_* columns, which are 0/stale for the renamed/edited formulas.

## Scoring

- `SessionManager.set_active_goal(metric_key, target=None)` — accrues `time_above_threshold`/`longest_streak` (and `avg_score`) against that metric and target (`None` → the session threshold), at the formula's own scale (independent of `meditation_threshold`'s 0–100 clamp). **A session is scored on the metric that drives the feedback sound (#51):** in a simple session — decided by `_session_program_active`, fixed at session start, never the editable `_timer_mode` toggle — `_update_tick` calls `_score_on_drive_key()` → `set_active_goal(self._audio_drive_key())` every tick and feeds the audio from that same resolved key (so scoring and sound can't diverge, and a mid-session audio-metric change or an invalid formula's shamatha fallback moves both), and the legend's `»` marks the scored series — the change rides the tick's single `_ui_update` dispatch via `_scored_mark(key)`, which leaves `_scored_key` untouched while the screen is locked so the first tick after it marks the change; a program session's segments set it instead. The per-tick accrual is `app/session/scoring.GoalAccrual` (also behind `goal_stats(values, goal)`, the recompute from stored ticks), and `recorded_score(session)` reads a stored row's `(key, name, avg)` — rows from before #51 have an empty `score_metric_key` and `recorded_score` returns `None` for them — nothing is deduced (their streak was in fact measured on meditation, but the metric was never saved), so the UI shows them as it did before #49 and stored rows are never rewritten. SessionManager reports no key and a NULL `avg_score` when no tick was scored (a session stopped within its first tick). **A running simple session's scored metric can't change**: `SessionManager` keeps one running sum, time above and streak, so a mid-session switch mixed two metrics' scales under the last one's name — `_on_audio_metric_change`, `_on_audio_formula_index` (when a formula slot drives) and `_on_formula_slot_change` (a formula change to the slot the sound is set to — a name-only rename passes) refuse while a simple session runs or connects (`_scoring_locked(doing)`: not `_session_program_active`, then the shared refusal — a program is scored on its segments' metrics, so the control stays free) and put Settings back (`_show_audio_metric`, `set_formula_slot`); the other slots and the threshold stay editable. Every such refusal — this one, the profile switch and both Restore checks — is `_refused_while_session_runs(doing)`: "Session in progress" / "Stop the current session before <doing>." Every checkpoint passes its stats through `_with_score`, which fills the key (the current drive key when none was scored) and adds `score_metric_name` (the live graph's `series_name(key)`, e.g. a formula's name) or, for a program, `"program"` + the program's name (`"Program"` if unsaved) + NULL `avg_score`. `_apply_program_tick` (called in `_update_tick`, program mode only) uses the pure `_program_transition` helper to detect a boundary crossing, then `_apply_program_segment` fires the prior segment's end cue (`AudioEngine.play_transition_cue()` chime, or warble), sets the **transient** `_program_audio_key` to the segment's metric key (from the precomputed `_program_segment_keys`) — it must NOT clobber the user's persisted `_audio_metric_key`, or a program slot leaks into the baseline and a later simple session reads that (absent) key as 0 → constant max noise — calls `set_active_goal`, and moves the legend marker; every program custom line is evaluated every tick (persistent `_program_formula_evs`, see [programs.md](programs.md)). Auto-stop reuses the timer-expiry path: the program total seeds the timer at session start.
- **The threshold in force** (#83): `SessionManager` scores a tick against `set_active_goal`'s target (a program segment) or else `_threshold`, moved by `set_threshold(value)` and by `start(threshold)` — `start()` without one keeps it, which is how a session that waited for the headset starts with a threshold changed during the wait; `threshold_used` stays the Start value (the row's). `_put_threshold_in_force(value)` is the one place the Settings threshold takes effect — the metrics engine, the sound, the SHAMATHA pill (`_shamatha_threshold`), `SessionManager.set_threshold` and the graph's scalar line, together. `_start_session_common` calls it directly (with a program's first target; a lingering tick thread from the last session must not block it); the slider's settle and the registry's profile load go through `_apply_threshold(value)`, which does nothing while `_program_owns_threshold()` (`_session_program_active and _session_pipeline_live()`: a running program's segments own its targets) — re-picking the active profile mid-program reloads its settings, and must not put the slider's value over a segment's target. During a running program the threshold controls are locked: `_start_session_common` calls `SettingsScreen.lock_threshold(_refuse_program_threshold)` and every ending (`_undo_session_setup`) `lock_threshold(None)`. A guard bound to the slider row's and the preset row's `on_touch_down` (bound handlers run before the widget's own and stop it by returning True) passes every touch on the slider, ±5 and the presets while locked to the callback, `_refuse_program_threshold`, and takes it only when that refused — `_refused_while_session_runs("changing the threshold", why=...)`, a message per touch, refusing only while the session pipeline is live — so between a program's end on the tick thread and its queued unlock the controls work rather than go dead; mouse-wheel events are taken too (Kivy's Slider steps its value on them). The lock is installed after the start's setup, so a start that fails in it leaves the controls as they were. The rows are dimmed (opacity 0.5). Nothing moves, so nothing is reverted or saved: a slider that moved and was then put back on its settle jumped under a resting finger, and its value could be flushed in between; a once-only message was easy to miss after several ± clicks. The slider applies it through `_after_settle("apply_threshold", …)` — the per-name Clock trigger restarted on every change that `_persist_user_setting_later` is built on, the same 0.5 s — so a drag is one change at the value it settles on, not a target per slider step on every tick it spans; Start cancels a pending one (`_settle_triggers["apply_threshold"]`), since the start reads the slider itself. A profile load sets the slider, so it also schedules one, which applies the same value again (harmless). With no session pipeline live, a change of the slider (`_on_threshold_change`, which Kivy calls only when its value changes — a profile switch to another stored threshold included) clears the Session screen's graphs and mirrors when they hold a finished session (`_clear_live_graphs`, also the Start's), since its stepped line would otherwise outrank the new scalar line. Re-applying an unchanged Settings value clears nothing: after a program the threshold in force is a segment's target, so comparing against it would wipe the graphs on a mere profile reload. `_put_threshold_in_force` is the only writer of `_shamatha_threshold` (a session's end no longer resets it to 50). Before, only the sound and the graph followed the slider: the scoring, the pill and the wait's start kept the Start value, and in a program the slider moved the sound off the segment's target. `add_metric` returns what the tick was scored on — `{score_key, score_value, score_target}`, `{}` when not RUNNING — and keeps the `(first tick, target)` steps with `scoring.extend_steps`, whose values are the stats' `score_targets` (JSON; `''` with no scored tick). `_record_tick` merges that into the tick's row; a tick the session paused or stopped under (`{}`) is not part of it — no row, mirror point or graph point, and a pending marker goes on the next recorded tick (it used to be stored, unscored). Per tick, not per session: a formula's values aren't stored otherwise, and a recompute (#50) needs what each tick was measured against.

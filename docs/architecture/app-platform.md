# App lifecycle, platform and build

The user gate and profiles, the Android back button, error reporting, test guardrails, and build/CI specifics. Hard rules are summarized under **Invariants** in [CLAUDE.md](../../CLAUDE.md); this file holds how the subsystem works and why.

## User gate and profiles

- **Hard user gate:** the app is never usable with no active user. `build()` gates on `resolve_startup_user(db)` (the resolved uid, or `None`) — NOT on `get_all_users()` emptiness, which let "users exist but `last_user_id` unresolved" (reinstall / restored DB / deleted-active-profile / corrupt `last_user_id`) slip into a usable-but-unset state. `None` → bottom nav disabled synchronously (no cold-start tap window) + blocking `_show_first_run_popup` (`self._gate_popup`, made un-escapable in `_on_keyboard`). Deleting the active profile re-enters the gate. Per-user handlers use `_require_user(action)` (surfaces a message, returns the uid or `None`) instead of a bare silent `return` — wired into `_on_program_save`/`_save_program` (empty-name / no-user / saved-programs cap) and `_on_program_load`/`_on_program_delete`/`_on_load_formula`/`_on_delete_formula`/`_open_saved_formula_chooser`. History/Diary go through `sessions_for_view(db, uid, show_all)`: the deliberate "Show All Users" view (`_view_all_users`, set only by `_on_user_switch(None)`) queries all sessions, a concrete user queries their own, and an **unset** user returns `[]` — so `_current_user_id=None` never leaks every profile's sessions. `on_resume` re-enters the gate if the process resumed unset (not All-Users). **Every path that picks a profile goes through `_activate_user(uid)`** (sets the id, clears `_view_all_users`, stores `last_user_id`, loads the settings) — startup restore, wizard-complete (new or adopted), the wizard's pick-existing path, and `_on_user_switch`; an activation that skipped the load left the previous/default values in memory under that profile, which the next flush (e.g. the pre-backup save) then wrote over its stored settings. `_on_user_switch` **refuses while `_session_pipeline_live()`** ("Session in progress", picker snapped back via `_refresh_profile`), including the All-Users view: the running session owns its loaded timer/threshold/sound settings and saves under the profile it started with.
- `DatabaseManager.create_user` raises `UserExistsError(user_id, name)` on duplicate. Wizard, first-run popup, and Settings → User Profile use the shared `UserPickerForm` widget (`app/ui/widgets/user_picker.py`); the form's "Use existing 'X'" button branch goes through `_on_pick_existing_user(user_id, source)` in `app_manager`. For `source="wizard"`, if the picked user has a saved `bt_device_address` per-user setting, step 2 (device picker) is skipped and the wizard completes with that device.

## Android back button

- Android hardware back button (`AppManager._on_keyboard`, bound to `Window.on_keyboard`): consumes key 27 (returns `True`) so Kivy's default exit-on-escape never fires, then routes by precedence — while the user gate is active (`_gate_active`, incl. the pre-popup schedule window), `_handle_gate_back` applies double-press-to-EXIT (never falls through into the app, but a fresh-install user who declines to create a profile can still leave); else an open `Popup`/`ModalView` is left to self-dismiss (handler returns `False`); else an open fullscreen graph overlay closes (via the stored `_fullscreen_close` `_restore` closure); else Diary detail → `_on_diary_back`; else any non-`live_session` screen → `_switch_screen("live_session")` (syncs the bottom-nav highlight); else on the Session root, **double-tap within 2 s exits** (`_last_back_time`), the first press showing the in-app `_toast` (the native `_android_toast` — `run_on_ui_thread` + pyjnius `Toast` — is kept for toasts raised while the app is leaving). **A Python `str` must cross pyjnius as `android_jni.java_string(text)`** whenever the Java method is overloaded: pyjnius scores a `str` 10 for both `String` and `char[]` and breaks the tie by sorting signatures (`[C` > `L`), so `Intent.putExtra(EXTRA_TITLE, str)` stored a `char[]` and the SAF save dialog's name came up blank; a `CharSequence` parameter never matches a `str` at all, so `Toast.makeText` raised on every call (the double-back toast never showed). Esc on desktop follows the same chain.

## Errors and diagnostics

- Global crash handler (`app/crash_handler.py`) installs `sys.excepthook`, `threading.excepthook`, and a Kivy `ExceptionManager` handler; all three funnel into a modal dialog that auto-copies a markdown report to the clipboard. Dismiss exits via `app.stop()`. Same module exposes `report_soft_error(label, detail, *, force=False)` for handled-but-significant errors — reuses the dialog with a non-fatal banner and "Close" button (no `app.stop`), and is gated by a 60 s per-label cooldown to prevent spam. Wired to BT connect failures and to the **Copy Diagnostics** button in Settings → Device (which passes `force=True` to bypass the cooldown).
- Perf instrumentation: `app/logger.py` `timed(label)` context manager logs `[PERF] label: N.Nms` when `EEG_PERF=1` (off by default). Wrap a block to benchmark it; on-device it needs a temporary `os.environ["EEG_PERF"] = "1"` at the top of `main.py`, since p4a passes no host environment to the app (`p4a_env_vars.txt` holds only p4a's own vars) — then grep logcat for `[PERF]`. Timing that must always be on stays aggregated instead (see `render_stats` in [eeg-bluetooth.md](eeg-bluetooth.md)).

## Tests

- `tests/test_silent_failure_guardrail.py` is an AST guardrail run on every `pytest` (issue #29 invariant): it scans `app/` and fails on a **silent user-gate return** (`if not self._current_user_id: return/pass` with no user-feedback call) or a **discarded bool-returning DB write** (`add_saved_program`/`add_saved_formula` result ignored). A legitimately-silent site is grandfathered with a standalone `# silent-ok: <reason>` marker (not a ruff noqa code) that must carry a reason. The gate itself is opened by the single `_open_user_gate(delay)` (build / on_resume / self-delete all route through it) and its decision is `resolve_startup_user(db)`.
- `conftest.py` only sets `sys.path` — no shared fixtures.

## Build and CI

**Removing an Android requirement doesn't remove it from local builds.** p4a keeps it installed in `.buildozer/android/platform/build-arm64-v8a/build/python-installs/eegmeditation/arm64-v8a/` and keeps reusing the dist `.buildozer/android/platform/build-arm64-v8a/dists/eegmeditation/` (its `dist_info.json` lists the recipes it was built with — a superset of the current ones still counts as a match), so every later APK keeps bundling it. A numpy probe (2026-10-01) left numpy + Cython (+16 MB) in every build after `numpy` was taken back out of `requirements`. After dropping a requirement, delete that package from `python-installs/` and the `dists/eegmeditation` folder (the next build recreates the dist in about a minute), then check the bundle: site-packages live inside `lib/arm64-v8a/libpybundle.so`, a tar inside the APK. CI builds start clean and are unaffected.

- Windows CI build sets `KIVY_DOC=1` in the PyInstaller spec to prevent GL init on headless runner; Kivy data paths (`kivy_install/data/`, `kivy_install/modules/`) are constructed manually instead of importing `kivy.tools.packaging.pyinstaller_hooks`.
- Linux CI uses system Python (ubuntu-24.04) instead of `actions/setup-python` to get `socket.AF_BLUETOOTH` support.
- MDI icon font path resolution tries multiple candidates for cross-platform compat (standard, Android, fallback).

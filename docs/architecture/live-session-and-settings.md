# Session screen, Settings, wizard

The live Session screen, the Settings screen and the first-run wizard. Hard rules are summarized under **Invariants** in [CLAUDE.md](../../CLAUDE.md); this file holds how the subsystem works and why.

## Session screen

- **Session screen** (`live_session.py`): Metrics/Raw EEG toggle (inline, no separate screen), connection overlay with status + countdown, session end summary card with quick notes (`show_summary(sid, stats, title=)`: Duration, the `session_score_rows` rows, Time Above Threshold and Longest Streak, 22 dp lines with no gap (`_set_summary_rows` attaches as many pooled rows as the session has). `_layout_summary` arranges it by the card's width, re-run on every width change, so a phone turned with the card open re-flows it with the typed notes kept: from 520 dp inside the card (a landscape phone, ~670) two columns — the stats left, the notes field over **Save notes** right (the field takes the column's remaining ~78 dp, a few lines) — else one column, the stats over the notes field, which is as tall as Save notes beside it; Delete and OK under both. The title follows the arrangement by the same rule, `_summary_in_two_columns`, applied to its own width, which spans the card's inside (`_fit_summary_title`, so it can't depend on which of the two width changes Kivy dispatches first): `Session saved · <session_title>` on one line over two columns, the name on a line of its own under `Session saved` over one, either cut with an ellipsis to its line (`_cut_to_width`), never wrapped further). Bottom-bar action buttons (Start/Pause/Stop/Mark) use a 2-row vertical layout (icon on top, text on bottom) via `StyledButton(vertical=True)`. Adaptive landscape layout: `_compute_graph_height_adaptive` uses a fixed graph height when viewport is tall, or switches to scroll mode when the graph would fall below `dp(400)`. Bottom bar lives inside the body ScrollView.
- Live Session layout uses `_compute_graph_height_adaptive`: fixed graph height when viewport is tall, scroll mode when the graph would fall below `dp(400)` (landscape). The bottom bar lives inside the body ScrollView.
- Stats card toggle: tapping the swap icon flips all 5 slots between live instant values and session aggregates (`avg_shamatha`, `avg_meditation`, `time_above_threshold`, `time_shamatha_90`, `longest_streak`). Mode persists per user via the existing JSON user-settings column.
- **Shamatha-reached status emphasis** (issue #13) — while the live `shamatha_score` holds at/above the session threshold the header status label becomes a bold `SHAMATHA` on a green `C.SHAMATHA` rounded pill; otherwise it shows the classified state. The pill is a `Color`+`RoundedRectangle` in `_state_label.canvas.before` sized to the text (`_position_shamatha_chip`, bound to the label's `texture_size`); `set_shamatha(active)` toggles its alpha and the text/`readable_fg(C.SHAMATHA)` color, and `update_state` records `_last_state` but skips restyling while the chip is active (the tick stream can't overwrite it). Crossing is detected by the pure `AppManager._shamatha_transition(active, above, streak, enter_ticks=3, exit_ticks=3)` on the tick thread (debounced: 3 ticks / 1.5 s each way against 2 Hz noise); only the *change* is dispatched to `set_shamatha`. Gated on the threshold in force — not per-segment program targets: a program's start puts its first segment's target in force (`_put_threshold_in_force`), and that gates the pill for the whole run. Reset at session start/stop and re-synced on Android resume. The pill's `Color` stays a plain instruction (its alpha is the on/off toggle; a `ThemedColor` would reset it on a switch) — `C.SHAMATHA` is the same in every palette, so it needs no repaint.

## Settings screen

- **Settings screen** (`settings_screen.py`): `ThemedAccordion` sections — User Profile, **Timer / Program**, Device, Data Backup, Threshold (max 180), Audio, Display, Custom Formula, Theme selector. User Profile section uses the shared `UserPickerForm`; Data Backup has Backup/Restore buttons. (Graph series selection moved to the on-graph picker; `_graph_toggles` remains only as the first-run default set.) Custom Formula section has **three named slots** (Slot 1/2/3), each with name input, expression input, Apply, Save, and per-slot status. A `[1][2][3]` button group below the "Custom Formula" audio-metric radio selects which slot drives noise (`set_audio_formula_index_callback` → `_on_audio_formula_index` in `app_manager`). **Timer / Program section** has a **Simple | Program** toggle: Simple = single duration + Enable-Timer checkbox; Program = segment editor (`_segments_box`, rows with duration, formula, target, end-cue picker (Chime/Warble), feedback-source picker) + loaded-program label (`_program_loaded_label`) + saved-programs library (save/load/delete named programs). The toggle swaps `_simple_box` or `_program_box` into `_mode_content_box` via `clear_widgets()`/`add_widget()` — a zero-height disabled container still lets children overflow and swallow taps, so the inactive box must be fully detached.
- **Device list** (Settings → Device). One row per paired device, `device_row_text(alias or Bluetooth name, address)` (`app/ui/device_labels.py`): every MindWave advertises the same name, so the address tells rows apart. The wizard's list uses the same row text.
  - **Marks:** the selected headset's row has the accent fill and the connected one the Bluetooth glyph (`_mark_bt_devices`); in mock mode no headset is in use, so none is marked. The screen reads them from `AppManager._device_state()` whenever it shows device status: a list populate, `update_device_status`, and `on_pre_enter`, since the link can drop between sessions with nothing on screen. Every row is built with the glyph so its slot exists (`StyledButton` makes an icon label only at construction) and `set_icon("")` blanks it.
  - **Names:** the pencil opens the inline editor History's rename uses (`theme.RenameRow`, stopping at `MAX_DEVICE_ALIAS` while typing) under the row; Save or Enter calls `AppManager._on_device_rename(address, bluetooth_name, text)`, which stores the alias and relabels the row (`relabel_bt_device`) and, for the headset in use, the status line and the Session screen's label (`_show_selected_device`, which a pick in the list goes through too). Aliases are app-wide, not per profile: `bt_device_aliases`, a JSON `{address: alias}` in `app_settings` (`get_json_setting`), because a headset is the same object whichever profile uses it; the selected headset stays per profile (`bt_device_address`). Blank, or the Bluetooth name itself, drops an alias, and one is cut to `MAX_DEVICE_ALIAS` (24) characters to keep its row on one line.
  - Everything that names the selected headset (status line, the Session screen's label, the connect overlays, session names) goes through `AppManager._device_name()`. A session's name is taken at its first checkpoint, so a later alias doesn't rename it.

## Wizard

- **Wizard** (`wizard_screen.py`): 2-step first-run (name → device scan/skip). Step 1 uses `UserPickerForm` so the user can pick an existing profile (e.g. after reinstall) without retyping the name. Hidden bottom nav during wizard. On Android, the form's TextInput hijacks focus to a Popup TextInput because Kivy TextInput doesn't get keyboard focus inside a Screen on some Android devices.

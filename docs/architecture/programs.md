# Session programs

Ordered timed segments: the model, how a program drives the live graph's series, and its Settings and session-screen controls. Hard rules are summarized under **Invariants** in [CLAUDE.md](../../CLAUDE.md); this file holds how the subsystem works and why.

## Model and storage

- **Session Program** (`app/session/session_program.py`): headless model — `SessionProgram` holds an ordered list of segments (duration, formula key, target, end-cue); exposes `total_seconds`, `segment_at(elapsed)`, `boundaries()`, and `threshold_steps(sample_rate)` (list of `(start_tick, target)` tuples in tick-index space, consumed by the graph). Settings → Timer has a **Simple | Program** toggle; Program mode reveals a segment editor (add/delete rows, formula picker with built-ins + saved custom formulas, target, end-cue) and a saved-programs library (save by name, load by tap, delete). Active program persists as `session_program` (JSON, per-user); `timer_mode` (`"simple"` | `"program"`) persists as a flat KV setting.
- `sessions.session_program` column stores the JSON-serialized `SessionProgram` for each session (empty string when no program ran). `saved_programs` per-user library uses `get/add/update/remove_saved_program` in `DatabaseManager` (JSON list in the user-settings KV store under key `user_{id}_saved_programs`).
- `_session_program_name` — active program name persisted per-user as `session_program_name` (flat KV) alongside the program JSON and `timer_mode`; restored on user load; shown in Settings via `set_program_name` and surfaced in the live-session duration picker.

## Live series

- **Program shows EXACTLY its metric set, the whole session** — the live graph catalog (`live_session.METRICS_COLORS`/`METRICS_SCALES`/`SERIES_NAMES`) carries `"meditation_score"` (color `C.MED_SCORE`, scale 100, label `"Meditation"`, so a "Meditation" segment is plottable — defaults **hidden** via first-run `_graph_toggles` + `_restore_graph_series`'s `key in sel`) and **three** program-custom lines `PROGRAM_FORMULA_KEYS = ("program_formula","program_formula_2","program_formula_3")` (colors `C.WARM`/`C.WARM2`/`C.WARM3`, scale 200), one per **distinct** custom formula in a program. `program_plan(prog)` (`app/session/session_program.py`, with `PROGRAM_FORMULA_KEYS`; the what-if replay uses it too) returns `(program_keys, custom_slots, segment_keys)`: the set of series to show, the `(slot_key, custom_dict)` map for each distinct custom (capped at 3), and the metric key each segment drives (built-in key or its custom's slot). `_show_program_series(prog)` snapshots prior visibility into `_program_prev_visibility`, shows EXACTLY `program_keys` (hides the rest), arms one persistent evaluator per custom into `_program_formula_evs[slot]` (`program_evaluators(prog)`), and stores `_program_segment_keys`. Each program line is shown the **whole** program and evaluated every tick (`_apply_program_tick` loops `_program_formula_evs` into `metrics[slot]`). `_apply_program_segment` repoints audio/goal/marker to `_program_segment_keys[idx]` (a built-in key or a program slot); `_apply_program_segment_ui` only relabels/shows a custom segment's line and moves the `»` marker (built-in segments touch no visibility). `_restore_program_series` restores the snapshot, resets all program-slot labels, and force-hides all `PROGRAM_FORMULA_KEYS`. `_resolve_segment_key` is the fallback for direct callers (unit tests) without a precomputed plan.
- `PROGRAM_FORMULA_KEYS` stay out of persistence (`_save_user_settings`/`_persist_graph_series` filter them via `k not in PROGRAM_FORMULA_KEYS`; `_restore_graph_series`/`_apply_saved_series` force-hide them) so they never leak into `graph_series_*`. `_present_series_picker` lists them (as `Program: <name>`) **only while a program is active** on the live graph. Idle preview (`_refresh_live_program_series`, wired through `_sync_live_timer_picker`): in program mode with a loaded program it shows the program's set via `_apply_program_visibility` before Start; otherwise `_apply_saved_series` restores the user's saved selection. `_program_governs_live_series()` gates persistence so a program's visible set never overwrites the saved manual selection. `_program_hidden_slots` is retained as a legacy no-op field.
- Legend "training now" marker — `LegendBar.set_items(items, active_text=None)` bolds the matching item and prefixes it with `"» "` (the `»` glyph; geometric triangles render as tofu in this Kivy/Roboto build). `LiveSessionScreen.set_training_series(key)` propagates the active key to the legend; `AppManager._apply_program_segment` calls it on each segment boundary crossing, and clears it (`None`) at session start/stop.

## Settings and pickers

- Settings Timer / Program swap — the Enable-Timer checkbox lives in `_simple_box` (hidden in program mode). `_program_loaded_label` shows `"Loaded: <name>"` via `set_program_name(name)` (`SettingsScreen`). `_segments_box` holds segment rows in program insertion order top→bottom.
- `_sync_live_timer_picker` — syncs the `_DurationPickerButton` label on the session screen: `"P"` (large) in program mode, duration string in simple mode. Re-synced whenever the screen is entered and whenever Settings timer changes. The duration popup includes a `"Programs…"` button wired via `LiveSessionScreen.set_session_programs(programs, current_name)` for quick-loading a saved program and showing the loaded name with the current one highlighted.
- Per-segment **feedback source picker** (issue #10): each program segment row has a "Feedback" column — a live picker with Default / Rain / Tone / Custom file. "Default" inherits the global Settings → Audio selection. The source switches at each segment boundary via `set_active_feedback` (setVolume-only, tick-/lock-safe). See [audio.md](audio.md) for the engine architecture.

# Session programs

Ordered timed segments: the model, how a program drives the live graph's series, and its Settings and session-screen controls. Hard rules are summarized under **Invariants** in [CLAUDE.md](../../CLAUDE.md); this file holds how the subsystem works and why.

## Model and storage

- **Session Program** (`app/session/session_program.py`): headless model — `SessionProgram` holds an ordered list of segments (duration, formula key, target, end-cue); exposes `total_seconds`, `segment_at(elapsed)`, `boundaries()`, and `threshold_steps(sample_rate)` (list of `(start_tick, target)` tuples in tick-index space, consumed by the graph). Settings → Timer has a **Simple | Program** toggle; Program mode reveals a segment editor (add/delete rows, formula picker with built-ins + saved custom formulas, target, end-cue) and a saved-programs library (save by name, load by tap, delete). Active program persists as `session_program` (JSON, per-user); `timer_mode` (`"simple"` | `"program"`) persists as a flat KV setting.
- `sessions.session_program` column stores the JSON-serialized `SessionProgram` for each session (empty string when no program ran). `saved_programs` per-user library uses `get/add/update/remove_saved_program` in `DatabaseManager` (JSON list in the user-settings KV store under key `user_{id}_saved_programs`).
- `ProgramSettings` (`app/ui/program_settings.py`, the app's `_program_settings`) holds what Settings → Timer edits: `mode` (`simple`/`program`), the editor's `segments` and its `name`, persisted per-user as `timer_mode`, the program JSON and `session_program_name` (flat KV); the name is restored on user load; shown in Settings via `set_program_name` and surfaced in the live-session duration picker.

## Live series

- **Program shows EXACTLY its metric set, the whole session** — the live graph catalog (`live_session.METRICS_COLORS`/`METRICS_SCALES`/`SERIES_NAMES`) carries `"meditation_score"` (color `C.MED_SCORE`, scale 100, label `"Meditation"`, so a "Meditation" segment is plottable — defaults **hidden** via first-run `_graph_toggles` + `GraphSeries.restore`'s `key in sel`) and **three** program-custom lines `PROGRAM_FORMULA_KEYS = ("program_formula","program_formula_2","program_formula_3")` (colors `C.WARM`/`C.WARM2`/`C.WARM3`, scale 200), one per **distinct** custom formula in a program. `program_plan(prog)` (`app/session/session_program.py`, with `PROGRAM_FORMULA_KEYS`; the what-if replay uses it too) returns `(program_keys, custom_slots, segment_keys)`: the set of series to show, the `(slot_key, custom_dict)` map for each distinct custom (capped at 3), and the metric key each segment drives (built-in key or its custom's slot). `ProgramRun` (`app/ui/program_run.py`, the app's `_program_run`) holds the running program: `active` from the start's `begin(prog, feedback_ids)` until `end()`. `begin` snapshots prior visibility, shows EXACTLY `program_keys` (`show_program_series` hides the rest), arms one persistent evaluator per custom into `formula_evs[slot]` (`program_evaluators(prog)`), and stores each segment's metric key. Each program line is shown the **whole** program and evaluated every tick (`tick` runs `formula_evs` into `metrics[slot]` through `custom_formula.evaluate_series`, as the Settings formulas are). `_enter_segment` repoints audio/goal/marker to the segment's key (a built-in key or a program slot); `_segment_ui` only relabels/shows a custom segment's line and moves the `»` marker (built-in segments touch no visibility). `end` restores the snapshot, resets all program-slot labels, and force-hides all `PROGRAM_FORMULA_KEYS`.
- `PROGRAM_FORMULA_KEYS` stay out of persistence (`GraphSeries.persist`, which `_save_user_settings` runs through `persist_all`, filters them via `k not in PROGRAM_FORMULA_KEYS`; `GraphSeries.restore`/`apply_saved` force-hide them) so they never leak into `graph_series_*`. `GraphSeries.present_picker` lists them (as `Program: <name>`) **only while a program is active** on the live graph. Idle preview (`ProgramSettings.refresh_live_series`, wired through `sync_picker`): in program mode with a loaded program it shows the program's set via `show_program_series` before Start; otherwise `GraphSeries.apply_saved` restores the user's saved selection. `governs_live_series()` gates persistence so a program's visible set never overwrites the saved manual selection.
- Legend "training now" marker — `LegendBar.set_items(items, active_text=None)` bolds the matching item and prefixes it with `"» "` (the `»` glyph; geometric triangles render as tofu in this Kivy/Roboto build). `LiveSessionScreen.set_training_series(key)` propagates the active key to the legend; `ProgramRun._segment_ui` calls it on each segment boundary crossing, and clears it (`None`) at session start/stop.

## Settings and pickers

- Settings Timer / Program swap — the Enable-Timer checkbox lives in `_simple_box` (hidden in program mode). `_program_loaded_label` shows `"Loaded: <name>"` via `set_program_name(name)` (`SettingsScreen`). `_segments_box` holds segment rows in program insertion order top→bottom.
- `ProgramSettings.sync_picker` — syncs the `_DurationPickerButton` label on the session screen: `"P"` (large) in program mode, duration string in simple mode. Re-synced whenever the screen is entered and whenever Settings timer changes. The duration popup includes a `"Programs…"` button wired via `LiveSessionScreen.set_session_programs(programs, current_name)` for quick-loading a saved program and showing the loaded name with the current one highlighted.
- Per-segment **feedback source picker** (issue #10): each program segment row has a "Feedback" column — a live picker with Default / Rain / Tone / Custom file. "Default" inherits the global Settings → Audio selection. The source switches at each segment boundary via `set_active_feedback` (setVolume-only, tick-/lock-safe). See [audio.md](audio.md) for the engine architecture.

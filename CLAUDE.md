# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

EEG Meditation Trainer — a Python/Kivy application for Shamatha meditation training using EEG neurofeedback from NeuroSky MindWave Mobile 2. Targets Android (via Buildozer), Linux, macOS and Windows (via PyInstaller) desktops.

## Commands

```bash
# Run application
python main.py

# Run with serial device (e.g. from mindwave-splitter)
python main.py --serial /tmp/mindwave_b

# Run all tests
python -m pytest tests/ -v

# Run a single test file
python -m pytest tests/test_engine.py -v

# Run a single test
python -m pytest tests/test_engine.py::TestMetricsEngine::test_compute_metrics -v

# Build Linux executable
./build_linux.sh              # output: dist/EEG_Meditation_Trainer/

# Build Android APK
./build_android.sh            # debug build
./build_android.sh release    # release build

# Build Windows executable (run on Windows)
build_windows.bat

# CI: build a single platform via workflow dispatch
gh workflow run release.yml -f platform=windows   # or linux, macos, android, all
```

## Architecture

**Entry point:** `main.py` → instantiates `EEGMeditationApp` (Kivy app with ScreenManager).

**Data flow:** EEG stream → MetricsEngine → SessionManager → UI screens + Database

### Core modules

- **EEG sources** (`app/eeg/`): `mock_stream_v2.py` (active mock with frequency-based synthesis, NeuroSky-compatible format), `mock_stream.py` (legacy mock), and `neurosky_stream.py` (real Bluetooth RFCOMM / pyserial, ThinkGear protocol). Both active sources produce 8 band powers + raw 512Hz waveform + eSense attention/meditation. Desktop BT falls back to PyBluez if `socket.AF_BLUETOOTH` is missing (common in PyInstaller bundles). Real stream tracks `_last_packet_time` for stale data detection and parses battery level (code 0x01, though TGAM hardware doesn't send it). BT connection kept alive between sessions to avoid RFCOMM/EBUSY issues; `reset_sample_state()` clears cached values for new sessions.
- **Metrics pipeline** (`app/metrics/engine.py`): Consumes raw band powers, computes meditation score, shamatha score, distraction, sinking, subtle distraction via sigmoid normalization. Uses rolling buffers from `app/eeg/buffer.py`. Power-line noise detection in `app/metrics/noise_detector.py`.
- **Custom formula engine** (`app/metrics/custom_formula.py`): AST-parsed user-defined expressions with whitelisted functions and `avg(expr, N)` windowed averages.
- **Session lifecycle** (`app/session/manager.py`): Start/Pause/Resume/Stop state machine. Coordinates EEG stream, metrics engine, audio feedback, and database flush. Tracks `time_shamatha_90` (time shamatha score >= 90, independent of user threshold).
- **Session program** (`app/session/session_program.py`): headless model for ordered timed segments — see Key Design Decisions.
- **Audio feedback** (`app/audio_feedback/noise.py`): 4-channel engine — selectable continuous feedback (log-scaled volume, MAX_VOLUME=0.3), tingsha bell (sinking), chime (subtle distraction), warble (disconnect alert). Uses Kivy SoundLoader with crossfaded WAV generation. On Android, the feedback channel and the **timer-end gong** use `MediaPlayer` (with `USAGE_MEDIA` audio attributes) instead of SDL_mixer so they keep playing through screen lock; SoundLoader/SDL is silenced while locked. The other one-shot channels (sinking bell, chime, warble) still use Kivy's `SoundLoader`. `AudioEngine.mute()` is a non-blocking volume→0 (setVolume only) safe to call from the tick thread during lock. **Selectable feedback source** (issue #10): `AudioEngine.prepare_feedback(sources, active_id)` (main-thread) pre-instantiates one looping player per distinct source id (`"noise"`, `"tone"`, or a custom file path); `set_active_feedback(source_id)` is setVolume-only — the active player goes to the modulated volume, all others go to 0. No player is created or released mid-session; switching is tick-/lock-safe under the same deadlock-avoidance rule as `mute()`. The `"tone"` source generates a harmonic-pad drone (fundamental + fifth) lazily at session start. `EEGMeditationApp._feedback_plan` / `_source_spec` / `_feedback_source_id` / `_global_feedback_id` resolve the global setting and per-segment override (`""` inherits global); `_apply_program_segment` calls `set_active_feedback` at each boundary. Persisted per-user: `feedback_source` (`"noise"` / `"tone"` / `"custom"`) and `feedback_sound_path`. This multi-player substrate is the foundation issue #12 (two simultaneous sounds) will extend.
- **Storage** (`app/storage/database.py`): SQLite with automatic schema migration. Stores sessions (with `session_name`, `time_shamatha_90` columns), per-tick metrics timeseries, user profiles, per-user settings. CSV export support. `create_user` raises `UserExistsError` on duplicate name; `find_user_by_name` looks up by exact (case-sensitive) name. Per-user settings are a flat KV store (`set_user_setting`/`get_user_setting`, key = `user_{id}_{key}`); `set_user_json_setting`/`get_user_json_setting` wrap a value as JSON in one key (the pattern used by `saved_formulas`, and by per-graph series / active-formula lists).
- **DB backup/restore** (`app/storage/backup.py`): `online_backup_to_tempfile` (SQLite online `Connection.backup()` into an internal temp file), `make_backup` (temp + `shutil.copy2`, desktop), `validate_backup` (checks for required tables), `restore_backup` (validates then `shutil.copy2`). Android backup/restore go through the Storage Access Framework (`app/storage/android_saf.py`) since scoped storage blocks direct `/sdcard` access. Used by Settings → Data Backup section.

### UI layer (`app/ui/`)

**Navigation:** 3-tab bottom bar (Session / History / Settings) via `BottomNav` in `theme.py`. First-run wizard shown when no users exist.

- **Theme system** (`theme.py`): Centralized `C` color accessor (4 palettes: Dark Blue, Dark Green, Light Cream, Light Green), `F` font sizes, `S` spacing. `format_duration(seconds)` — smart time display (seconds if <1m, minutes if <1h, hours otherwise). `make_scroll_popup(title, rows, footer=None, *, est_rows=None, ...)` — the shared builder for every list-style select dialog (series picker, saved-formula chooser, program picker, duration picker): the `rows` scroll inside a `ScrollView` with the `footer` pinned below, sized to content but capped at 85% of the window so long lists scroll instead of overflowing. `est_rows` overrides the height estimate when a row is itself a multi-row grid. Custom widgets: `StyledButton` (rounded, press feedback, MDI icons, outline mode; `vertical=True` for 2-row icon-top/text-bottom layout), `Card`, `Divider`, `ThemedAccordion`, `PresetRow`, `RevealBox`, `BottomNav`. Theme changes notify listeners for live refresh. `StyledButton` resolves its text/icon colour by **role** (re-applied on bg/theme change, never a frozen snapshot): no `text_color` → **AUTO** = `readable_fg(bg_color)` picks the light or dark glyph with the higher WCAG contrast against *that button's* background (fixes both light-icon-on-light-accent and dark-icon-on-saturated-fill — every action button ends ≥4.4 CR on all 4 themes); explicit `C.TEXT`/`C.TEXT_SECONDARY` follow that theme role; any other colour is fixed. **Disabled** dims both label and icon to 60% of `readable_fg(bg)` (a dimmed auto-contrast grey, ~4:1, theme-independent — the theme's light `C.TEXT_MUTED` washed out on light cards); the dimmed colour is written to the labels' **`disabled_color`** as well as `color`, because Kivy's `Label` style draws `disabled_color` (default white@.3 → invisible on light cards) whenever the widget is disabled — setting only `color` left the disabled action-bar glyphs blank on light themes. **pressed** only darkens the background (glyph colour unchanged). The class-level `text_color` default was a frozen import-time ~white that rendered icons invisible on light themes (disabled buttons hit ~1.25 CR); theme switching is a pure live-refresh (no screen rebuild), so the role must re-resolve on `C.add_listener`. **`RevealBox(content_height)`** is the sanctioned touch-safe way to conditionally show a row: `set_content(*widgets)` once, then `reveal(bool)` — it **detaches** the children when hidden (empty box at height 0) rather than collapsing them in place. Never hide interactive content with `height=0`/`opacity=0`/`disabled=True`: Kivy's `Widget.on_touch_down` does `if self.disabled and self.collide_point(...): return True`, so a hidden-but-attached disabled widget *consumes* taps on whatever it overlaps (a known Kivy bug, unfixed in 2.3.x; `on_touch_up`/`on_touch_move` ignore-without-consuming). `tests/test_touch_regression.py` enforces this: it mounts screens in a real window and flags both actual dead zones and the collapse-in-place anti-pattern (a disabled, collapsed container still holding interactive children).
- **Icons** (`app/assets/fonts/materialdesignicons-webfont.ttf`): Material Design Icons font, registered as `'Icons'`. `ICONS_AVAILABLE` flag for graceful fallback if font missing.
- **App icons** (`app/assets/icons/`): Generated EEG brainwave icon (512/192/128/48 PNG + ICO + ICNS), presplash for Android.
- **Session screen** (`live_session.py`): Metrics/Raw EEG toggle (inline, no separate screen), connection overlay with status + countdown, session end summary card with quick notes. Bottom-bar action buttons (Start/Pause/Stop/Mark) use a 2-row vertical layout (icon on top, text on bottom) via `StyledButton(vertical=True)`. Adaptive landscape layout: `_compute_graph_height_adaptive` uses a fixed graph height when viewport is tall, or switches to scroll mode when the graph would fall below `dp(400)`. Bottom bar lives inside the body ScrollView.
- **History screen** (`history_screen.py`): Calendar/14-Day segmented toggle at top — `CalendarHeatmap` (GitHub-style, by avg shamatha) or `Last14DaysBars` (per-day bar chart). Both share `set_data(day_values)` + `set_day_tap_callback` so tap-to-filter works in both modes. Selected mode persisted as per-user setting `history_view_mode`. Day filter, session list with inline rename/delete unchanged.
- **Settings screen** (`settings_screen.py`): `ThemedAccordion` sections — User Profile, **Timer / Program**, Device, Data Backup, Threshold (max 180), Audio, Display, Custom Formula, Theme selector. User Profile section uses the shared `UserPickerForm`; Data Backup has Backup/Restore buttons. (Graph series selection moved to the on-graph picker; `_graph_toggles` remains only as the first-run default set.) Custom Formula section has **three named slots** (Slot 1/2/3), each with name input, expression input, Apply, Save, and per-slot status. A `[1][2][3]` button group below the "Custom Formula" audio-metric radio selects which slot drives noise (`set_audio_formula_index_callback` → `_on_audio_formula_index` in `app_manager`). **Timer / Program section** has a **Simple | Program** toggle: Simple = single duration + Enable-Timer checkbox; Program = segment editor (`_segments_box`, rows with duration, formula, target, end-cue picker (Chime/Warble), feedback-source picker) + loaded-program label (`_program_loaded_label`) + saved-programs library (save/load/delete named programs). The toggle swaps `_simple_box` or `_program_box` into `_mode_content_box` via `clear_widgets()`/`add_widget()` — a zero-height disabled container still lets children overflow and swallow taps, so the inactive box must be fully detached.
- **Shared widgets** (`widgets/`): `UserPickerForm` (used by wizard step 1, first-run popup, and Settings → User Profile) — existing-profiles list + name input + duplicate-name "Use existing 'X'" / "Change name" inline UI. `LoadingOverlay` (`widgets/loading_overlay.py`) — app-global dimmed modal spinner (status + animated dots, theme-aware) mounted by wrapping the app root in a `FloatLayout`; shown via `EEGMeditationApp.show_loading(text)`/`hide_loading()`. Because it animates via `Clock`, the caller must move the long work off the main thread or the overlay can't paint.
- **Wizard** (`wizard_screen.py`): 2-step first-run (name → device scan/skip). Step 1 uses `UserPickerForm` so the user can pick an existing profile (e.g. after reinstall) without retyping the name. Hidden bottom nav during wizard. On Android, the form's TextInput hijacks focus to a Popup TextInput because Kivy TextInput doesn't get keyboard focus inside a Screen on some Android devices.
- **Diary detail** (`diary_screen.py`): Session stats, notes/tags/mood, graph tabs (metrics/raw/freq). Navigated from History, with back button. Per-session custom-formula series are **replayed**: `_on_session_select` → `_inject_session_formulas` rebuilds the evaluators from the session's recorded `custom_formulas` JSON and recomputes their series via `recompute_formula_series`, then calls `set_session_formulas(series, names)` (which `_load_graph_data` uses to override the stored custom_formula_* columns and renames the series). Injection runs after `show_session_detail` (which resets `_session_formula_series`) and before `load_metrics_preview`.

**Configuration:** All tunable parameters (sigmoid curves, thresholds, update frequency, audio settings) are in `app/config.py` as dataclass-style config objects (`SIGMOID`, `METRICS`, `APP`).

### Diagnostic tools (`tools/`)

- `bt_test.py` — Minimal raw RFCOMM + ThinkGear parser for connection debugging. No Kivy, no threads. Usage: `python tools/bt_test.py [MAC]`
- `ble_battery_scan.py` — BLE GATT service enumerator (requires `bleak`). MindWave Mobile 2 doesn't expose BLE on Linux/Android (iOS only).

## Key Design Decisions

- Update loop runs at 2Hz (`AppConfig.UPDATE_FREQUENCY = 0.5s`), graph holds 600 points (5 min).
- Band powers are sqrt-normalized to relative units before metric formulas.
- NeuroSky Bluetooth uses pyjnius on Android, Python socket BTPROTO_RFCOMM on Linux (with PyBluez fallback), pyserial over virtual COM port on Windows. BT connection is kept alive between sessions (not closed on session stop) to avoid RFCOMM EBUSY and ThinkGear reinit failures. On app exit, the socket is NOT explicitly closed — the kernel handles cleanup while BlueZ may keep the ACL link for faster next-launch reconnect. Connection timeout is 30s, signal wait is 8s. Stale data (no new packets for 10s) auto-stops the session.
- Android DB path always uses `app_storage_path()` (not `/sdcard`) for stable path across launches. Old DB auto-migrated on first run. `KIVY_KEYBOARD_MODE=systemanddock` + `softinput_mode=below_target` set for Android TextInput stability.
- Desktop DB path resolves to platform user-data folder: Linux `${XDG_DATA_HOME:-~/.local/share}/EEGMeditation/`, Windows `%APPDATA%\EEGMeditation\`, macOS `~/Library/Application Support/EEGMeditation/`. One-time migration copies any pre-existing DB from next-to-binary or project root; the old file is left in place for manual rollback.
- DB migrations (Android `/sdcard → app_storage_path` and desktop legacy → user-folder) surface failures via `crash_handler.queue_pre_app_error(label, detail)`, replayed by `EEGMeditationApp.on_start()` through `report_soft_error`. **Project policy:** never `except (PermissionError, OSError): pass` — surface a diagnostic instead.
- `DatabaseManager.create_user` raises `UserExistsError(user_id, name)` on duplicate. Wizard, first-run popup, and Settings → User Profile use the shared `UserPickerForm` widget (`app/ui/widgets/user_picker.py`); the form's "Use existing 'X'" button branch goes through `_on_pick_existing_user(user_id, source)` in `app_manager`. For `source="wizard"`, if the picked user has a saved `bt_device_address` per-user setting, step 2 (device picker) is skipped and the wizard completes with that device.
- Backup/Restore lives in `app/storage/backup.py`. Backup uses SQLite's online `Connection.backup()` API (transaction-safe). **`online_backup_to_tempfile(db)` writes the online backup to a temp `.db` beside the live DB (internal storage) and returns its path; callers byte-copy or stream it out, then delete it** — SQLite returns `SQLITE_CANTOPEN` ("unable to open database file") if asked to open/lock a DB directly on Android FUSE storage (`/sdcard`) or a `content://` URI, so the destination is never opened by SQLite. `make_backup(db, path)` wraps it + `shutil.copy2` (desktop / real filesystem paths). **Android uses the Storage Access Framework** (`app/storage/android_saf.py`), not a hardcoded path — scoped storage (targetSdk 30+) forbids direct `/sdcard` writes regardless of `WRITE_EXTERNAL_STORAGE`/`MANAGE_EXTERNAL_STORAGE` (the latter doesn't even exist on API 29). Backup: `_run_backup_saf` → SAF `ACTION_CREATE_DOCUMENT` save dialog (user picks location) → `online_backup_to_tempfile` → `android_saf.write_file_to_uri` streams the temp through the returned `content://` URI via `ContentResolver.openOutputStream`. Restore: `_run_restore_saf` → SAF `ACTION_OPEN_DOCUMENT` → `android_saf.read_uri_to_file` streams the picked file to an internal temp (`FileUtils.copy`, API 29+) → normal validate + restore. No storage permission, survives uninstall, works API 29→34+. `android_saf` routes results via a request-code registry bound once to `android.activity.on_activity_result`; all pyjnius imports are function-local so it imports cleanly off-Android. Desktop backup/restore worker catches `(OSError, sqlite3.Error)`; the SAF worker catches broadly (pyjnius boundary) and `report_soft_error`s. Restore validates the file (must contain `users` and `sessions` tables), closes the live DB, copies over `APP.DB_PATH`, then force-restarts via a "Please relaunch" popup → `App.stop()` (in-memory caches reference the old DB, simpler to restart). Desktop uses Kivy `FileChooserListView` save/open popups.
- `history_view_mode` per-user setting (`"calendar"` | `"bars"`, default `"calendar"`) selects the History layout via `HistoryScreen.set_view_mode(mode)`. Both `CalendarHeatmap` and `Last14DaysBars` consume the same `day_avg` dict and share the tap-to-filter callback.
- Removed dead code in this iteration: `app/ui/analytics_screen.py`, `app/ui/home_screen.py`, `app/analytics/aggregator.py` — all unreachable from the bottom nav (only Session/History/Settings).
- Database opens with `check_same_thread=False` so the daemon tick thread can safely write metric batches.
- `conftest.py` only sets `sys.path` — no shared fixtures.
- Volume curve uses log scaling (`k=9`): rises fast initially, flattens near max (0.3). Prevents harsh noise at low scores.
- Theme colors accessed via `C.PRIMARY` etc. — `C` is a `_ColorAccessor` instance that reads from a mutable dict. `C.set_theme(name)` swaps palette and notifies listeners.
- Settings saved in `on_pause()` (Android) and `on_stop()` (desktop) so they persist when OS kills backgrounded app. `on_pause()` always returns `True` — per Kivy docs, returning `False` stops the app rather than "refusing to pause" (counter-intuitive but documented).
- Session tick runs in a Python daemon thread (`SessionTick`) instead of Kivy `Clock` so EEG compute, audio volume updates, and DB flushes continue while the Android screen is locked. UI updates are dispatched via `_on_main` (`Clock.schedule_once`); they queue during pause and drain on resume.
- Session names auto-generated as `"HH:MM - DeviceName"` to distinguish mock vs real.
- Windows CI build sets `KIVY_DOC=1` in the PyInstaller spec to prevent GL init on headless runner; Kivy data paths (`kivy_install/data/`, `kivy_install/modules/`) are constructed manually instead of importing `kivy.tools.packaging.pyinstaller_hooks`.
- Linux CI uses system Python (ubuntu-24.04) instead of `actions/setup-python` to get `socket.AF_BLUETOOTH` support.
- MDI icon font path resolution tries multiple candidates for cross-platform compat (standard, Android, fallback).
- Live Session layout uses `_compute_graph_height_adaptive`: fixed graph height when viewport is tall, scroll mode when the graph would fall below `dp(400)` (landscape). The bottom bar lives inside the body ScrollView.
- `ScrollableGraphWidget` (`app/ui/raw_eeg_screen.py`) is the single time-series graph class — every per-session/diary graph is an instance of it. Cross-graph affordances live here once, not per screen: `set_expand_callback(cb)` reveals a top-right fullscreen-expand glyph (drawn into `_gfx` by `_draw_expand_icon`, hit-tested at the top of `on_touch_down` *before* `touch.grab`). Both glyphs are theme-aware with a transparent background: `_draw_icon_backing` only sets the glyph color to `TC.TEXT` (no chip/fill/border) so the strokes draw straight onto the graph and contrast on every palette — light on dark themes, dark on light (a former fixed black-backing/white-glyph read as a grey box on light themes and darker-than-bg on dark; intermediate grid-tone chips, solid then gradient-edged, were discarded as too heavy). The fullscreen overlay's Close control matches: a transparent `Icons.CLOSE_CIRCLE_OUTLINE` `StyledButton` in `C.TEXT` (`padding=[0,0]` so the circular glyph isn't cropped), replacing the former red text button. The **series picker** is a second canvas glyph (top-left list icon) via `set_series_picker_callback` — both are drawn into `_gfx` and share the window-coordinate hit-test (`_touch_in_window_rect`), so neither can be starved by the ScrollView the way an overlaid Kivy widget is. The picker is wired on **every** graph (live metrics/raw/band + diary metrics/raw/freq) by `AppManager._wire_graph_affordances` (the single source of truth for both glyphs, iterating `_all_graphs()`); it is gated to graphs with **>1 series** since a single-series graph's picker could only blank the line. One presenter, `_present_series_picker(graph)`, reads the graph's **own** catalog/labels/colors (`series_keys()` / `series_name()` / `series_color()`) — no hardcoded metric list. Each graph carries a `graph_id` (`live_metrics`, `live_band`, `diary_metrics`, `diary_freq`, …) and its selection persists per-graph as `graph_series_<graph_id>` (JSON, per-user); the live metrics graph additionally migrates legacy `toggle_<key>` rows when it has no JSON yet, other graphs default to all-visible. `set_visible` fires the graph's `visibility_callback`, so the owning screen's legend (visible-filtered) and the fullscreen legend both refresh on any picker toggle *or* restore. The **custom_formula** validity gate (`self._custom_formula.is_valid`) applies only to the live metrics graph — diary custom_formula is recorded data and toggles freely.
- **Glyph hit-testing is done in WINDOW coordinates** (`_touch_on_expand_icon`). The graph sits inside a `GraphAwareScrollView` that forwards touches in a mid-chain frame matching **neither** the canvas-drawn rect (`touch.x/y`) **nor** a `to_widget`/`to_local` conversion — verified by on-device click logging, each was off by a different amount. The only unambiguous frame is the window: compare the touch's canonical window position (`touch.sx*Window.width, touch.sy*Window.height`) against the glyph's rendered window rect (`self.to_window(...)` of `_expand_icon_rect`). The draw (`_draw_expand_icon`) and the hit-test use the **same** rect, so the visible box is exactly the tap target (no padding mismatch). `app/ui/touch_utils.point_in_rect` is the shared rect test. The History/user-picker manual routers happen to work with raw `collide_point` because their handlers are bound where the touch is already in the right frame — they're not under `GraphAwareScrollView`.
- **`GraphAwareScrollView.on_touch_down`/`on_scroll_start` only intercept touches inside the ScrollView's own viewport** (`self.collide_point` guard). A graph's *logical* bounds extend past the visible viewport when the body overflows (scroll mode), so `_graph_under_touch` would otherwise match — and steal — touches aimed at widgets sitting outside the scroll (e.g. the Metrics/Raw toggle above it). Regression-tested in `tests/test_ui_widgets.py::TestGraphAwareScrollViewGuard`.
- Fullscreen expand (`EEGMeditationApp._present_graph_fullscreen`, wired by `_wire_graph_expand`): **reparents** the graph (not a clone) into a full-window `FloatLayout` overlay on `self._float_root` with `size_hint=(1,1)` + `pos_hint={"x":0,"y":0}` so it reaches every edge — a `Popup` insets its content with chrome. Reparenting keeps the single `Window.on_mouse_down` bind and the live `add_point` feed, so a running session graph updates live in fullscreen. The expand glyph is hidden (`set_expand_callback(None)`) while fullscreen; Close restores the graph to its original parent/index. **Capture `list(size_hint)`/`list(size)` copies before overriding** — they are live `ReferenceListProperty`s; a bare reference tracks the `(1,1)` you set and breaks restore.
- Android hardware back button (`AppManager._on_keyboard`, bound to `Window.on_keyboard`): consumes key 27 (returns `True`) so Kivy's default exit-on-escape never fires, then routes by precedence — an open `Popup`/`ModalView` is left to self-dismiss (handler returns `False`); else an open fullscreen graph overlay closes (via the stored `_fullscreen_close` `_restore` closure); else Diary detail → `_on_diary_back`; else any non-`live_session` screen → `_switch_screen("live_session")` (syncs the bottom-nav highlight); else on the Session root, **double-tap within 2 s exits** (`_last_back_time`), the first press showing a `_android_toast` (`run_on_ui_thread` + pyjnius `Toast`, no-op off Android). Esc on desktop follows the same chain.
- Diary session-open is async behind a spinner: `_on_session_select` calls `show_loading()` then defers `_load_session_async` one frame (so the overlay paints first). The worker thread does the DB-heavy work — `get_session`, `_compute_session_formulas` (pure recompute, no Kivy — split out of `_inject_session_formulas` which stays as the sync compute+apply used by tests), `get_session_metrics`, `get_session_band_totals` — then `_on_main(_render_session_detail)` does all Kivy mutation and `hide_loading()` (in a `finally`). DB reads off-thread are safe (`check_same_thread=False` + WAL).
- **Per-band power breakdown** (issue #8) — the diary detail shows total power per frequency band over the whole session via `BandTotalsView` (`app/ui/widgets/band_totals.py`): 8 rows (delta…gamma2), each a band-colored bar whose width is the band's **share** of total power, labeled with the absolute total (`format_power`: K/M) + percent. Computed **on read** — `DatabaseManager.get_session_band_totals(session_id)` runs one `SELECT SUM(<band>_raw)` over the already-recorded per-tick band powers, so there's **no schema change** and the live tick path is untouched. Fed from the diary async worker → `_render_session_detail(..., band_totals)` → `diary_screen.set_band_totals`. Pure helpers `band_shares` (zero-total safe) and `format_power` are unit-tested; sub-bands share their group color (alpha1/alpha2 → alpha, etc.). The live end-summary deliberately does **not** show it (fixed, full layout).
- Diary raw-EEG `_synthesize_waveform` synthesizes only the **tail** the graph retains (`_RAW_MAX_SAMPLES = sample_rate*60`), starting the global sample index at the first kept tick so the tail is phase-identical to a full synthesis; returns `(waveform, start_tick)` so raw markers map tail-relative. Avoids computing ~99 % discarded samples on long sessions (3.6 s → 75 ms for 47 min).
- History list builds in chunks: `HistoryScreen._show_sessions` queues `_build_row_chunk` via `Clock` (`_ROW_CHUNK` rows/frame) instead of one synchronous loop, so 76+ rows don't freeze the UI; `load_sessions(sessions, on_complete=...)` fires the callback after the last chunk (wired to `hide_loading`). `_cancel_row_build` cancels an in-flight build on re-entry (rapid day-filter taps).
- All legends use one wrapping `LegendBar` (`app/ui/widgets/legend.py`, a `StackLayout` flow): `set_items([(text, rgba)])` flows colored labels and wraps to extra rows (each label sized to its text), so many series (6 metrics + 3 custom formulas) stay readable instead of overlapping in a single-row `BoxLayout`. Used by the live metrics/band legends, the diary legend, and the fullscreen legend.
- Perf instrumentation: `app/logger.py` `timed(label)` context manager logs `[PERF] label: N.Nms` when `EEG_PERF=1` (off by default). Wrap a block to benchmark it on-device (grep logcat for `[PERF]`).
- Global crash handler (`app/crash_handler.py`) installs `sys.excepthook`, `threading.excepthook`, and a Kivy `ExceptionManager` handler; all three funnel into a modal dialog that auto-copies a markdown report to the clipboard. Dismiss exits via `app.stop()`. Same module exposes `report_soft_error(label, detail, *, force=False)` for handled-but-significant errors — reuses the dialog with a non-fatal banner and "Close" button (no `app.stop`), and is gated by a 60 s per-label cooldown to prevent spam. Wired to BT connect failures and to the **Copy Diagnostics** button in Settings → Device (which passes `force=True` to bypass the cooldown).
- BT auto-connect picks the single matching MindWave automatically. When more than one paired device matches the `mindwave`/`neurosky` name filter, the auto-scan and start-session paths route the user to Settings → Device, expand the section, scroll it into view, and surface a "pick one" banner with only the matching devices listed. The banner is cleared by `update_device_status(connected=True)`. Helper: `EEGMeditationApp._filter_mindwave`; UI hook: `SettingsScreen.focus_device_section(message)`.
- `_AccordionSection` (`app/ui/theme.py`) binds `_content.minimum_height` to `_update_height` so its inner `_scroll.height` tracks growth from grandchildren added after the section was opened — without it, lists populated post-open (e.g. `populate_bt_devices` after the user expanded Device) get clipped to the original empty-content height.
- Android sessions hold a `PARTIAL_WAKE_LOCK` and run a foreground service (`service/session_keep_alive.py`, declared via `services =` in buildozer.spec) for multi-hour locked-screen operation. `SessionManager.stop(reason)` plays a short warble alert only for **failure** terminations (`stale_data`, `bt_lost`, `error`); `user` and `timer` are planned stops and stay silent (`timer` plays its own gong).
- **Android MediaPlayer teardown must never run on the tick thread.** `MediaPlayer`'s event handler lives on the main Looper, which is paused while the screen is locked, so `release()`/`stop()` from the daemon tick thread deadlocks against it (hung tick thread → session never saved, noise never stops). `setVolume()` has no Looper sync and is safe from the tick thread. Rule: silence on the tick thread with `AudioEngine.mute()`; defer the real `AudioEngine.stop()` / gong `release()` to the main thread. The timer-end path persists the session on the tick thread *before* any audio call so a hang can never cost the session.
- Session persistence is split: `_persist_session_data(reason)` (tick-thread-safe DB write, no Kivy) + `_finalize_stop_ui(stats, id)` (main-thread UI teardown). `_stop_and_save` runs both on the main thread; the timer-expiry path runs `_persist_session_data` on the tick thread and defers `_finalize_stop_ui` via `_on_main`.
- Three custom-formula evaluators are keyed by `FORMULA_KEYS = ("custom_formula", "custom_formula_2", "custom_formula_3")` in `app_manager.py`. `_formula_for_key(key)` maps a series key to its `CustomFormulaEvaluator`; `_formula_slots[i]` holds the evaluators; `_formula_names[i]` holds the display names (default `"Custom 1/2/3"`). Slot names are pushed to the graph via `graph.set_series_name(key, name)`. Active names + expressions persist as `active_formulas` (JSON list of `{name, formula}`, per-user); the audio-driving slot index persists as `audio_formula_index` (flat KV string, per-user). At load time `_read_active_formulas_with_migration` seeds slot 1 from the legacy `custom_formula` scalar if no JSON exists yet. The audio binding: when "Custom Formula" is selected as the audio metric, `_audio_metric_key = FORMULA_KEYS[_audio_formula_index]`; if that slot's evaluator is invalid (empty or parse error), the noise-volume step falls through to shamatha. `_audio_drive_key()` resolves the live drive key: the program's transient `_program_audio_key` while a program runs, else the user's baseline; it falls back to `shamatha_score` for an invalid formula slot **or** a `PROGRAM_FORMULA_KEYS` value outside a program (those are absent from `metrics` → would read 0 → constant max noise). `_baseline_audio_metric(key)` keeps program slots out of the persisted/baseline `audio_metric` (sanitized on both save and load — load also heals a previously leaked value). The on-graph series picker shows a **Choose…** button next to each custom-formula row on the *live metrics* graph; pressing it opens a library popup and calls `_apply_library_to_slot(slot_idx, name, formula)` which updates the evaluator, the settings UI, and the graph name in one step. All three formula series share one Y-axis (scale 200, reference at 100).
- Active custom formulas are recorded at save time so the diary can replay them: every `save_session` call site (`_persist_session_data`, `_finish_stop`, the 60s partial flush) passes `custom_formulas=self._session_custom_formulas_json()` — a JSON string of the valid slots (`name`, `formula`, `visible`, `drove_audio`). `save_session(..., custom_formulas: str = "")` stores the **already-serialized string** (the contract; callers `json.dumps` at the site). It's built from `self._formula_slots[i].formula` + `graph.is_visible(FORMULA_KEYS[i])` (a pure dict read, tick-thread-safe). On diary load the diary recomputes from these defs (see Diary detail) rather than trusting the stored custom_formula_* columns, which are 0/stale for the renamed/edited formulas.
- After a session that ended during a screen lock, the live graph is reloaded from the session-lifetime mirror buffers via `_reload_live_graphs_from_mirror()` (used on both Android resume and finish) — the locked portion never reached the live graph through the per-tick `add_point`, so without this the graph would show only the pre-lock seconds while History shows the real duration.
- Kivy `Popup` chrome is always dark and is never themed, so popup body text uses the theme-independent `theme.POPUP_TEXT` (light) — `C.TEXT` is dark in the light palettes and renders invisible dark-on-dark.
- Stats card toggle: tapping the swap icon flips all 5 slots between live instant values and session aggregates (`avg_shamatha`, `avg_meditation`, `time_above_threshold`, `time_shamatha_90`, `longest_streak`). Mode persists per user via the existing JSON user-settings column.
- Meditation timer is split: a headless `TimerState` (`app/session/timer_state.py`) drives the tick-loop countdown; all user-visible controls — enable, duration, custom-sound path, browse and test — live in the Settings → Timer accordion (`SettingsScreen`). When the timer expires (on the daemon tick thread), the order is: persist the session via `_persist_session_data(reason="timer")`, `AudioEngine.mute()` the noise (non-blocking), `_on_main(_finish_on_main)` to defer `_audio.stop()` + `_finalize_stop_ui` to the main thread, then `play_timer_sound()` **last** (one-shot `MediaPlayer` gong, rings through lock). Persisting first and ringing last means a hung audio call can never cost the session or the summary. The gong plays until the file ends or the user taps Save / View in History / Close, each of which calls `AudioEngine.stop_timer_bell()` (releases the gong `MediaPlayer` on the main thread); `_start_session_common` also calls it pre-emptively to kill any long custom gong still ringing from a previous session.
- **Session Program** (`app/session/session_program.py`): headless model — `SessionProgram` holds an ordered list of segments (duration, formula key, target, end-cue); exposes `total_seconds`, `segment_at(elapsed)`, `boundaries()`, and `threshold_steps(sample_rate)` (list of `(start_tick, target)` tuples in tick-index space, consumed by the graph). Settings → Timer has a **Simple | Program** toggle; Program mode reveals a segment editor (add/delete rows, formula picker with built-ins + saved custom formulas, target, end-cue) and a saved-programs library (save by name, load by tap, delete). Active program persists as `session_program` (JSON, per-user); `timer_mode` (`"simple"` | `"program"`) persists as a flat KV setting.
- `SessionManager.set_active_goal(metric_key, target)` — accrues `time_above_threshold` against the active segment's metric/target at the formula's own scale (independent of `meditation_threshold`'s 0–100 clamp); defaults to `meditation_score`/`_threshold_used` so simple sessions are unchanged. `_apply_program_tick` (called in `_update_tick`, program mode only) uses the pure `_program_transition` helper to detect a boundary crossing, then `_apply_program_segment` fires the prior segment's end cue (`AudioEngine.play_transition_cue()` chime, or warble), sets the **transient** `_program_audio_key` to the segment's metric key (from the precomputed `_program_segment_keys`) — it must NOT clobber the user's persisted `_audio_metric_key`, or a program slot leaks into the baseline and a later simple session reads that (absent) key as 0 → constant max noise — calls `set_active_goal`, and moves the legend marker; every program custom line is evaluated every tick (persistent `_program_formula_evs`, see below). Auto-stop reuses the timer-expiry path: the program total seeds the timer at session start.
- `ScrollableGraphWidget.set_threshold_steps(steps)` / `threshold_value_at(tick)` — piecewise threshold rendering: the dashed threshold line follows a list of `(start_tick, target)` steps instead of a single scalar. Used on both the live metrics graph (updated each tick) and the diary metrics graph (replayed from `sessions.session_program` at diary load). Single-value threshold path unchanged (`set_threshold(value)` still works; `steps=None` reverts to scalar).
- `sessions.session_program` column stores the JSON-serialized `SessionProgram` for each session (empty string when no program ran). `saved_programs` per-user library uses `get/add/update/remove_saved_program` in `DatabaseManager` (JSON list in the user-settings KV store under key `user_{id}_saved_programs`).
- Per-segment **feedback source picker** (issue #10): each program segment row has a "Feedback" column — a live picker with Default / Rain / Tone / Custom file. "Default" inherits the global Settings → Audio selection. The source switches at each segment boundary via `set_active_feedback` (setVolume-only, tick-/lock-safe). See Audio feedback bullet above for the engine architecture.
- `theme.CenteredTextInput` — `TextInput` subclass; `halign="center"` (native Kivy 2.3) + padding-based vertical centering (`_recenter` adjusts `padding[1]`/`padding[3]` to `(height - line_height) / 2` on each resize, since Kivy has no `valign`). All single-line inputs use it; the two multiline fields (diary notes, live-session quick notes) keep plain `TextInput`.
- **Program shows EXACTLY its metric set, the whole session** — the live graph catalog (`live_session.METRICS_COLORS`/`METRICS_SCALES`/`SERIES_NAMES`) carries `"meditation_score"` (color `C.MED_SCORE`, scale 100, label `"Meditation"`, so a "Meditation" segment is plottable — defaults **hidden** via first-run `_graph_toggles` + `_restore_graph_series`'s `key in sel`) and **three** program-custom lines `PROGRAM_FORMULA_KEYS = ("program_formula","program_formula_2","program_formula_3")` (colors `C.WARM`/`C.WARM2`/`C.WARM3`, scale 200), one per **distinct** custom formula in a program. `_program_plan(prog)` returns `(program_keys, custom_slots, segment_keys)`: the set of series to show, the `(slot_key, custom_dict)` map for each distinct custom (capped at 3), and the metric key each segment drives (built-in key or its custom's slot). `_show_program_series(prog)` snapshots prior visibility into `_program_prev_visibility`, shows EXACTLY `program_keys` (hides the rest), arms one persistent evaluator per custom into `_program_formula_evs[slot]`, and stores `_program_segment_keys`. Each program line is shown the **whole** program and evaluated every tick (`_apply_program_tick` loops `_program_formula_evs` into `metrics[slot]`). `_apply_program_segment` repoints audio/goal/marker to `_program_segment_keys[idx]` (a built-in key or a program slot); `_apply_program_segment_ui` only relabels/shows a custom segment's line and moves the `»` marker (built-in segments touch no visibility). `_restore_program_series` restores the snapshot, resets all program-slot labels, and force-hides all `PROGRAM_FORMULA_KEYS`. `_resolve_segment_key` is the fallback for direct callers (unit tests) without a precomputed plan.
- `PROGRAM_FORMULA_KEYS` stay out of persistence (`_save_user_settings`/`_persist_graph_series` filter them via `k not in PROGRAM_FORMULA_KEYS`; `_restore_graph_series`/`_apply_saved_series` force-hide them) so they never leak into `graph_series_*`. `_present_series_picker` lists them (as `Program: <name>`) **only while a program is active** on the live graph. Idle preview (`_refresh_live_program_series`, wired through `_sync_live_timer_picker`): in program mode with a loaded program it shows the program's set via `_apply_program_visibility` before Start; otherwise `_apply_saved_series` restores the user's saved selection. `_program_governs_live_series()` gates persistence so a program's visible set never overwrites the saved manual selection. `_program_hidden_slots` is retained as a legacy no-op field.

- **Shamatha-reached status emphasis** (issue #13) — while the live `shamatha_score` holds at/above the session threshold the header status label becomes a bold `SHAMATHA` on a green `C.SHAMATHA` rounded pill; otherwise it shows the classified state. The pill is a `Color`+`RoundedRectangle` in `_state_label.canvas.before` sized to the text (`_position_shamatha_chip`, bound to the label's `texture_size`); `set_shamatha(active)` toggles its alpha and the text/`readable_fg(C.SHAMATHA)` color, and `update_state` records `_last_state` but skips restyling while the chip is active (the tick stream can't overwrite it). Gated on the meditation threshold only — **not** per-segment program targets. Reset at session start/stop and re-synced on Android resume. `_refresh_theme` re-resolves the pill + text color on theme switch.

## Documentation Rules

**All documentation files must stay in sync with code changes.** When modifying features, UI, commands, architecture, or build process, update the relevant docs in the same commit or PR:

- `CLAUDE.md` — Architecture, commands, design decisions. Update when adding/removing modules, changing build process, or altering key patterns.
- `readme.md` — English README: features, project structure, build instructions, setup. Update when adding user-visible features or changing platforms/dependencies.
- `readme_ua.md` — Ukrainian README: mirror all `readme.md` changes in Ukrainian.
- `docs/USER_MANUAL.md` — English user manual. Update when UI flow, screens, or settings change.
- `docs/USER_MANUAL_UA.md` — Ukrainian user manual: mirror English manual changes.
- `app/assets/help/help_en.txt` — In-app help content (English). Update when features, connection flow, or settings change.
- `app/assets/help/help_ua.txt` — In-app help content (Ukrainian): mirror English help changes.
- `CHANGELOG.md` — Release history in Keep a Changelog format. Add entries under `[Unreleased]` as you commit; promote to a new version section when tagging.
- `IMPROVEMENTS.md` — Roadmap. Mark items as completed when implemented; add new ideas as they emerge.
- `pyproject.toml` — Ruff config. Run `ruff check app/ tests/ main.py` before every commit; all checks must pass.
